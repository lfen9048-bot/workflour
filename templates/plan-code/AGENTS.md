# 项目协作约定

本项目使用 `plan-code` v2；先读 `PROJECT-WORKFLOW.md`、`.workflour/handoff.json`、`HANDOFF.md` 和当前派单。角色独立于模型。

- `plan-lead` 是共享项目状态唯一维护者，维护 `.workflour/handoff.json`、派单账本和最终计划。大管家只转交与汇报。
- 两名 Plan 成员按“负责人调研初案 → 评审具体质疑 → 负责人定稿”协作。保留原始需求、真实来源、用户约束、团队假设和验收标准；不强制无关实现细节。
- 默认仅 `code-main` 完整实现、整合、自测。确有独立子任务才启用 `code-helper` 并明确文件归属。
- `code-review` 独立审查代码和测试；`plan-review` 实际使用产品，保留浏览器交互与桌面/手机截图。工具不足时记录具体阻塞，不把单元测试等同体验通过。
- 每人仅写自己的 `records/<role>/` 和派单允许的代码。测试使用 `check.py test -- ...`，plan-code 默认只生成独立测试记录；回传记录路径让负责人导入。不得自行改共享状态。
- 实现或测试/依赖文件改变后，旧审核、测试和体验快照失效。技术和产品返工共用最多两轮；停止先核对原生派单和磁盘，明确继续后才能续跑。
- 不反向委派给祖先 Bot；用原派单回传。已完成、等待审批和仍运行的任务不重派。新项目使用独立会话和真实目录。
- 全权限不代表文件隔离；凭据不得写入材料。按职责按需读取技能，不另建一套调度器。
- `acceptance` 为待用户验收，只有用户明确确认才可 `done`；Bot 不代签。
