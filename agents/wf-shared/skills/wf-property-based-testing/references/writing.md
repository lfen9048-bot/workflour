# 编写与执行属性测试

先写出可证伪的句子：“在这些前置条件下，调用真实入口后必须满足这个关系”。说明一种错误实现为何会违反它；如果测试对任何返回值都通过，先改属性。测试不必穷举所有代数性质，选择能保护本次需求的关系即可。

## 生成输入

- 把范围和结构放进生成器，例如有上界的整数、合法记录、列表与其有效索引；有关联的字段从同一结构派生。避免独立生成再大量过滤，记录有效样本不足或过滤耗尽。
- 明确合法域和应拒绝的非法域。非法域测试断言约定的拒绝方式与副作用，不只是任意异常；不能以“输入非法”为由忽略接口承诺的错误处理。
- 保留已知关键边界：空值、单元素、重复、上下限、分隔符或 Unicode 中与格式有关的情况。使用库的显式例子或现有回归用例，让发现过的边界每次都检查。
- 不生成与契约无关的超大数据或无限操作序列。只为真实承诺的行为设计状态转换，使用独立的简化状态模型，不能复制生产逻辑。

## 执行与复现

沿用现有 Hypothesis/fast-check 版本与项目运行命令；需要 API 细节时查该版本文档或已有测试，不臆造装饰器、配置字段或缩减能力。生成器中使用库提供的随机来源；不要混入未控制的系统时间、外部网络或独立随机数。

为当前任务设合理的样例数、输入大小和执行超时。已有项目配置优先；观察到超时或有效样本不足时先找原因，不统一关闭超时、屏蔽健康检查或无限增加预算。大规模 fuzz、夜间任务和新的 CI 流程不由本技能自动创建。

每个样例隔离可变状态，必要时保留输入快照，避免被测函数原地修改输入后使比较对象一起变化。文件和持久状态使用临时资源；在失败与取消时也清理本次资源。属性执行的重复调用不得触及真实收费、通知或不可逆业务操作。

失败时先保留库报告的最小反例及其 seed/replay 信息（工具支持时），再用单个确定输入重现。缩减后的反例可以成为普通回归用例，但后续仍应分别说明生成测试与确定性回归的执行结果。

## 代码难以观察时

先通过现有公开入口、输入快照或可控依赖验证行为。若有小范围、保持接口不变的测试入口调整确有价值，说明它能验证什么，再按当前编码授权处理；独立审核只提出建议。不要为得到往返属性而额外开发用户未要求的解析器，也不为测试单方面重构整个模块。
