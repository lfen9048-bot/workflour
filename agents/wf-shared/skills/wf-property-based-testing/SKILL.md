# 属性测试

当代码有明确的不变量、往返关系或独立参照实现，并且输入组合多到少量例子容易遗漏时使用。适合解析、序列化、规范化、排序及状态转换；普通界面检查、文案修改或没有可信属性的小逻辑用示例测试即可，不为应用本技能而重构产品。

## 先确认契约与工具

从用户要求、已采用的格式规范、接口说明和有效测试确认输入域与预期行为；函数名和当前实现只提供线索，不能替代契约。检查项目现有测试配置及依赖：Python 常见 Hypothesis，JavaScript/TypeScript 常见 fast-check。保留现有测试框架与运行方式，不自动安装库或迁移框架。

项目没有 PBT 库时，先用现有框架补充有价值的边界/回归例子，明确执行范围。没有专用库也可以用明确的性质检查有限枚举或生成输入；如实区分固定例子、穷举、抽样及实际生成机制，不能把它们说成已使用 Hypothesis/fast-check 或具备未实现的自动缩减。若增加 PBT 库的收益明确，向实现负责人给出具体属性、依赖与成本，作为后续选择；不把安装依赖作为完成普通任务的前提。

## 选择能约束实现的属性

| 属性 | 使用条件与必要补充 |
| --- | --- |
| 往返 `decode(encode(x))` | 比较契约允许的等价值；格式会正规化或有损时不能要求原样恢复。两端也可能共享错误，因此已知格式样例或独立校验仍有价值。 |
| 幂等 `f(f(x)) == f(x)` | 仅在操作承诺稳定规范化时适用；总返回同一常量也可能满足，需要结合结果含义或保留信息的约束。 |
| 不变量 | 检查承诺的范围、元素保留、状态关系或合法转换；排序不能只检查长度，还要按契约检查顺序与元素是否丢失。 |
| 独立参照 | 参照须可信且独立；不要用被测函数本身或逐行复制实现当答案。 |

断言强度应由真实契约决定，不把交换律、浮点精确相等或可逆性套到所有函数。“没有崩溃”只在明确的健壮性契约下有意义，不能代替正确结果。

`f(f(x)) == f(x)` 是有效的幂等性质，不等于纯函数的 `f(x) == f(x)`。它可能抓到不稳定变换；只是单独通过幂等性仍不能证明排序保留了元素和次数，不能因为约束不充分就把这个性质判成无效。

- 编写生成器、控制执行范围或考虑测试入口时，读 [编写与执行](references/writing.md)。
- 复核已有属性测试或分析最小反例时，读 [复核与失败归因](references/reviewing-and-failures.md)。

结果注明属性依据、生成域、实际工具/命令与代码快照、执行范围和限制；失败保留可复现反例，涉及敏感输入时先脱敏。生成测试通过只说明执行范围内未发现反例，不能证明所有输入正确。审核者按原职责报告，协作编码只改已分配范围；不创建额外代理或新流程。
