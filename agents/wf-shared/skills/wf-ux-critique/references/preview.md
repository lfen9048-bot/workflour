# 关键预览

本阶段确认方向，不代替正式验收。新页面或明显视觉、交互方向变化时，运行关键页面并查看实际截图；无法运行时区分静态观察与未验证行为，给负责人明确缺口。浏览器方法使用现有 [wf-webapp-testing](../../wf-webapp-testing/SKILL.md)，复用已验证工具。

围绕主要用户任务检查：第一眼能否找到主要动作；分组、层级、术语和状态是否容易理解；关键操作是否符合预期；代表性窄屏是否仍可使用。普通工作台重视清楚、稳定和有效密度，不以展示页装饰作为质量要求。

优先指出会使实现方向返工的问题。报告当前截图或操作证据、影响和最小建议，区别方向性问题与可在收尾处理的局部问题。不要顺手重新设计已认可部分，也不把每种边界状态和所有浏览器都塞进预览。意见交当前实现者或负责人，按既有委派关系回传。
