# 最终体验

先核对验收条件、当前实现与已有有效证据；确认实际运行的页面对应被审核版本。按现有 [wf-webapp-testing](../../wf-webapp-testing/SKILL.md) 完成真实操作与读图，不重复搭建浏览器或进行无关能力探测。

从验收中的主要路径选一个有代表性的用户视角，完成任务而非只看首页。围绕该路径选择适用检查：

- 当前状态、操作结果和下一步清楚；错误可理解、可恢复，取消或返回不让用户丢失必要上下文。
- 加载、空数据、失败与成功反馈存在且准确；只测试本功能可能出现的状态。
- 标签和焦点使键盘路径可达，主要动作不依赖悬停；相关控件有可访问名称，文字和控件可读。
- 在约定桌面与窄屏下，主次、分组和文字换行合理；真实长内容不会遮挡关键操作。

将功能阻断、误导或不可访问排在样式不一致之前。只报告实际问题和重要验证缺口，格式为“位置/复现 → 证据 → 用户影响 → 最小修复建议”，附结论与未覆盖范围。与既有设计不同但仍满足需求的偏好不算缺陷。

实际读图工具不可用时，附已观察事实和能力缺口回传 blocked，停止追加同类实验；不能以“再测另一台设备”替代缺失图像输入。

截图只能证明可见状态，缩小视口不能证明真实触摸或 Safari 行为；如未测试应如实说明。实现变化使旧证据失效时重核受影响部分。结论交 Plan 负责人汇总，最终状态仍由用户验收决定。
