# Ubuntu 虚拟机：完整七 Bot 开发工作流

本入口部署大管家、Plan Team、Code Team 和通用助手。目标是 **Windows 宿主里的 Ubuntu 24.04 LTS 桌面版、x86_64**，不是 Windows 原生、WSL 或 ARM。沿用仓库已有团队和精简工作台；不把正在进行的前端演练当作已验收版本。

初次安装由虚拟机上的维护 Agent 执行下面的命令即可；账号登录需要你在 Ubuntu 浏览器中完成。部署之后日常使用直接给大管家发消息，不需要自己运行项目初始化命令。

仓库：[lfen9048-bot/workflour](https://github.com/lfen9048-bot/workflour)。也可以把 [接手提示词](01-给Ubuntu上的Agent.md) 整页交给虚拟机中的 Agent。

## 1. 准备虚拟机

建议分配 4 核、8 GB 内存和至少 30 GB 可用磁盘；这是起步建议，不是性能保证。保持 Ubuntu 桌面用户登录，允许网络访问 GitHub、npm、Node、WorkBuddy 和 Google。Windows 休眠、虚拟机暂停和网络中断都会影响工作中的任务。

在 Ubuntu 终端确认并下载：

```bash
uname -m
cat /etc/os-release
sudo apt-get update
sudo apt-get install -y git python3
mkdir -p "$HOME/projects"
cd "$HOME/projects"
git clone https://github.com/lfen9048-bot/workflour.git
cd workflour
./scripts/workflour-ubuntu.sh install --system-deps
```

应看到 `x86_64` 和 Ubuntu。不要整段使用 `sudo`，只给系统依赖安装提权。不要放在 Windows 共享盘里运行：Linux 原生目录更适合权限、软链接和依赖构建。安装器会拒绝在 Mac 或其他未支持平台执行。

安装内容：固定版本 DSH、pnpm、WorkBuddy 插件、OpenMausBot，隔离的 Playwright 环境及 Chrome、中文字体、用户级后台配置。已有 Node 24+ 和 npm 时复用；否则下载版本清单中的 Node 并核对 SHA256。**不会安装小红书采集服务，不会复制原电脑的密钥或登录态，也不会发测试模型请求。** 版本见 [versions.json](../../integrations/ubuntu/versions.json)。Antigravity 使用下一步的官方安装器，实际版本需在目标机记录。

## 2. 登录 WorkBuddy 并选账号池

```bash
./scripts/workflour-ubuntu.sh auth-workbuddy
```

在 **Ubuntu 的浏览器** 打开 `http://127.0.0.1:3080`，进入插件里的 WorkBuddy 设置：

1. 登录你准备使用的国内和国际账号。若仍要四个号参与，逐个登录并勾选；安装器不会自动寻找或添加未选账号。
2. 国内池和国际池分别启用，确认成员和顺序已保存。
3. 刷新模型目录，勾选 DeepSeek V4.1 Flash、Kimi K3.1 Pro、GLM-5.3-Flash 等需要的模型。
4. 检查用于体验评审的**具体模型 ID**是否支持并已启用图片输入；名字相似不能证明能力相同。
5. 保存后，在启动设置服务的终端按 Ctrl-C 返回。账号保留在本机 `~/.dsh`。

Ubuntu 默认从 **web profile** 读取账号设置；Mac 原流程继续默认 desktop。已有目标机可以在第一次安装前指定绝对 `DSH_HOME` 和 `WORKFLOUR_DSH_SOURCE_PROFILE`。工作台中七个 Bot 各自有独立 DSH profile；WorkBuddy 只是模型与额度通道，不额外创建 WorkBuddy Bot。

## 3. 安装和登录 Gemini 的 Antigravity

```bash
curl -fsSL https://antigravity.google/cli/install.sh -o /tmp/workflour-agy-install.sh
bash /tmp/workflour-agy-install.sh
./scripts/workflour-ubuntu.sh auth-gemini
```

按官方 CLI 提示登录自己的 Google 账号；成功后退出交互界面。桌面密钥环提示需要在 Ubuntu 解锁。若 `agy` 在自定义位置，运行配置前设置 `AGY_BIN` 为它的绝对路径。

Gemini 3.8 Flash 及 High 档位必须由这台机器的实时目录提供；账号地区、订阅、额度和图片能力另行验证。没有该模型时部署器会明确失败，不会悄悄换成别的模型。

## 4. 配置、启动和创建七个 Bot

```bash
./scripts/workflour-ubuntu.sh configure
./scripts/workflour-ubuntu.sh up
./scripts/workflour-ubuntu.sh connect
./scripts/workflour-ubuntu.sh doctor
```

`configure` 生成六个 DSH profile、一个 Antigravity 实例、本机七个全新 Bot ID、Obsidian 笔记入口和精简工作台副本。它不发送任务。`up` 启动工作台、自动记录计时器和每日检查计时器。`connect` 从实际模型目录核对后创建、突出显示并读回团队；重复执行不重复创建，不覆盖已有 Bot 的手选模型。

首次后台尚未启动完成时，可以等几秒重跑 `connect`。模型目录缺项时先修复登录或插件设置再重试，不要修改角色默认值掩盖缺项。

如果提示某实例目录尚未确认，先用 `python3 scripts/bot-model.py refresh --instance omb-wf-plan-lead` 刷新所报实例（把实例名替换为错误中那一个），再重跑 `connect`。这一步获取真实目录，不发送业务提示词。网络错误发生在创建中途时，保留原私有部署清单，仍重跑 `connect` 完成未确认的初始化，不删除清单或另造一套ID。

在 Ubuntu 浏览器打开 **http://127.0.0.1:8799**。这个地址属于虚拟机，Windows 浏览器的同名地址不是它。默认不开放公网、不关闭鉴权、不自动绑定所有网卡。若原来已经部署了小红书工作台，先检查已有服务并在空闲时停下：两个后台不能同时争用 8799。它们可以共享本机工作台数据，连接七角色时保留其他 Bot；本教程不自动迁移正在运行的任务。

| 角色 | 初始模型 | 思考 |
| --- | --- | --- |
| 大管家 | DSH / WorkBuddy DeepSeek V4.1 Flash | Low |
| Plan · 项目负责人 | DSH / WorkBuddy Kimi K3.1 Pro | High |
| Plan · 方案与体验评审 | DSH / WorkBuddy DeepSeek V4.1 Flash | High |
| Code · 主编码 | Antigravity / Gemini 3.8 Flash | High |
| Code · 独立审核 | DSH / WorkBuddy GLM-5.3-Flash | High |
| Code · 协作编码 | DSH / WorkBuddy DeepSeek V4.1 Flash | High |
| 通用助手 | DSH / WorkBuddy DeepSeek V4.1 Flash | Low |

角色与模型分开。通过大管家或通用助手的安全设置卡选择“当前任务”或“设为默认”；忙碌任务先结束，跨运行时新建任务并读交接。原生顶部菜单可能改 Bot 默认，不把它当成只改当前任务。

Bot 配置沿用 Full 文件/命令权限，浏览器使用独立测试上下文，桌面屏幕控制保持关闭。原生产品对新 Full 任务还有单独策略限制；若提示不允许，新建 Ask 任务并按需要审批，不伪造权限或关闭产品检查。角色职责不是操作系统沙箱。

## 5. 从工作台交第一个项目

在“大管家”中新建对话，发送下面的内容，把 `/home/你的用户名` 换成自己的 Ubuntu 路径：

```text
请让 Plan Team 和 Code Team 做一个简单的中文阅读清单网页。
新项目目录：/home/你的用户名/projects/reading-list
支持添加书名、标记已读、删除、筛选和刷新后保存。
请检查空输入、保存失败、键盘操作和375px手机宽度。
保留真实测试与截图，做完停在待我验收。
```

项目目录必须是全新或空目录。大管家转交 Plan 负责人，后者创建模板、写需求和账本；不要求你手工执行 `new-project.py`。

正常顺序：**大管家转交 → Plan 调研/初案 → Plan 评审 → 定稿 → 单主编码 → 独立技术审核 → Plan 实际体验 → 待你验收**。协作编码只在存在明确独立子任务时加入。方案讨论最多两轮，技术与体验返工共用两轮；超限或缺能力就报告具体阻塞，不假装完成。

询问“现在到哪一步、谁在做、为什么等待”，由大管家根据 Plan 的记录汇报。需要停止时使用当前任务的停止按钮；继续时明确说继续这个项目，由负责人先核对旧回执，不能直接重派整单。

## 6. 查看本地记录与验收

默认知识库：`$HOME/Documents/Obsidian/Workflour`。可以安装 [Obsidian 官方 Linux 版](https://obsidian.md/download)，选择“打开本地文件夹”，打开该目录；也可以直接用文本编辑器读 Markdown。安装器不要求必须安装 Obsidian 应用。

- `首页.md`、`项目经理.md`：本机入口与手写进度。
- `07-自动记录/`：已注册项目的进度、角色可见记录、测试证据链接和异常。
- 每个业务项目的 `.workflour/coordination.json`、`HANDOFF.md`、`records/`：原始共享状态和角色产物；以原件为准。
- OpenMausBot 和 DSH 本地数据目录：原生对话与运行记录，独立于 Git 仓库。

观察器每20秒只读同步已注册项目；它不派单、不确认审批、不替用户验收。新项目注册失败时修复知识库路径后重新 register，不重复 init。可以在配置前设置 `WORKFLOUR_OBSIDIAN_VAULT` 为自己的绝对知识库路径；初始化保留既有笔记。

最后你亲自打开实际页面，检查需求、关键操作和手机效果，再向大管家或项目负责人明确“验收通过”或给修改意见。截图文件存在、单元测试通过、模型说完成，都不能独自代替实际体验与用户验收。

## 7. 每日13点与额度规则

继续沿用：实时核实的免费线路 → 国内/国际临期额度 → 其他 WorkBuddy 额度 → 已有 DeepSeek API。国内和国际只使用你在当前 Ubuntu 插件里勾选的账号。新机器没有配置 DeepSeek API 时，不会从 Mac 找密钥；最后备用是否可用需本机确认。

北京时间每天 **13:00** 的 systemd 用户 timer 执行已勾选国内账号的签到读回，再检查恢复状态。模型恢复本身由插件在13点后的新回合进行，运行中的回合不打断，手选模型和 Bot 默认不被覆盖。计时器支持错过后的补查；是否签到成功看本地读回记录，不能单凭定时器触发认定成功。国际账号不参加国内签到。

重要限制：便宜线路不一定能看图，原 Mac 曾遇到 `deepseek-v4.1-flash-sg` 文本限定。体验阶段遇到这种情况必须回传受阻，按当前任务设置选择支持图片的可用模型后重新检查。Antigravity 没有自动跨运行时备用。

## 8. 日常维护与更新

```bash
./scripts/workflour-ubuntu.sh status
./scripts/workflour-ubuntu.sh doctor
./scripts/workflour-ubuntu.sh down
```

`down` 在 Bot/任务忙碌或工作台状态不明时拒绝停止。它会停用自己管理的服务和计时器；不要用 `killall node`。`up` 不会抢占一个已经在服务的工作台。用户级服务依赖 Ubuntu 用户登录及虚拟机持续运行，没有擅自开启系统级常驻或改变 Windows 电源设置。

更新时先检查任务空闲，再执行 `down`、`git pull --ff-only`、`install --system-deps`、`configure`、`up`、`connect`；有角色职责更新时再执行 `instructions`。不要重建现有业务项目或删除私有部署清单。命令细节以 `./scripts/workflour-ubuntu.sh --help` 为准。

机器私有位置：

| 内容 | 默认位置 |
| --- | --- |
| Ubuntu 工具运行时、设置和精简UI | `~/.workflour/ubuntu/` |
| 七 Bot ID 清单 | `~/.workflour/team-v2/deployment.json` |
| DSH账号/模型状态 | `~/.dsh/` |
| 工作台会话与数据 | `~/.openmausbot/` |
| 浏览器Python环境 | 仓库 `.tools/browser/` |
| 观察器注册与运行状态 | `~/.workflour/observer/` |
| 签到结果 | `~/.workflour/workbuddy/checkin-state.json` |

这些私有内容不要上传 GitHub。Git 保存部署代码、角色、技能、说明和筛选后的证据，不保存账号和运行中会话。

## 9. 验证边界与排障

安装检查和代码测试结果见 [本次Ubuntu验证记录](02-验证与已知限制.md)。`doctor` 不调用模型；工具就绪不代表登录、额度、图像或业务验收通过。第一次实际派单仍需检查全部实际能力，不能把 Mac 历史截图当成 Ubuntu 成果。

| 现象 | 优先检查 |
| --- | --- |
| 3080/8799打不开 | 是否在Ubuntu浏览器；服务是否启动；端口是否被另一套工作台占用 |
| WorkBuddy设置缺失 | 是否进入web profile；插件5.13.1是否安装；登录与模型选择是否已保存 |
| 创建Bot报模型不存在 | 实时目录、供应商和精确modelId；不要静默替换默认模型 |
| Gemini登录或启动失败 | 官方安装路径、桌面密钥环、账号订阅与网络；不要改用DSH冒充成功 |
| 看图提示text only | 当前实际路由及图片输入开关；报告blocked，不能仅看DOM就通过体验 |
| 自动记录没有项目 | 检查观察器、知识库路径、项目注册；不重复派单或重建账本 |
| 停止后想继续 | 明确继续原项目，先核对原生回执和停点；不新建同需求重复任务 |

## 方案来源

2026-11-12复查实际文档后，继续复用已有脚本和上游能力：

- [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)：MIT，官方npm/Web入口；版本迭代快，本项目固定已用版本。
- [WorkBuddy插件](https://github.com/dingminhua/dsh-connect-workbuddy)：MIT，浏览器登录、国内/国际账号池及精确模型能力。不是额外Agent。
- [OpenMausBot](https://github.com/milind-soni/OpenMausBot)：Apache-2.0，原生工作台、ACP和委派；沿用项目固定0.1.143及精简层。
- [Antigravity Linux CLI](https://antigravity.google/docs/install?tab=cli)：官方安装和登录，账号/订阅按目标机实际状态；未引入第三方ACP替身。
- [Playwright Linux浏览器](https://playwright.dev/python/docs/browsers)：复用隔离Chrome检查，不接管个人浏览器profile。
- systemd为Ubuntu原生后台管理；替代Mac launchd，不要求Docker承载登录密钥环和桌面浏览器。
