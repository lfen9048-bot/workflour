# 交给 Ubuntu 上的维护 Agent

请在当前Ubuntu虚拟机部署本仓库的**完整七Bot开发工作流**，不是小红书三Bot。

先读 `docs/ubuntu-deployment/00-从这里开始.md`、`02-验证与已知限制.md`、`AGENTS.md` 和仓库当前状态。使用现有 `scripts/workflour-ubuntu.sh`，不要另写一套编排器、搬Mac账号或创建 `/Users/a1`。

具体步骤：

1. 核对 Ubuntu 24.04 桌面 x86_64、Python、磁盘、网络；记录本机仓库绝对路径。若已有工作台/忙碌Bot，先只读检查，不能覆盖或中断。
2. 执行 install --system-deps；固定依赖版本，失败看日志处理，不静默升级包。
3. 打开 auth-workbuddy 供用户在Ubuntu浏览器登录国内/国际账号、选择账号池、模型及已支持的图片输入。不要输出Cookie或令牌。不要把四个账号当成自动存在。
4. 按官方安装器安装Antigravity，用auth-gemini让用户登录；记录实际版本，核验本机目录是否含Gemini3.8Flash/High。
5. 执行configure、up、connect、doctor。核对七个不同本机ID、角色职责、默认模型/思考、模型菜单及私有记录路径。登录完成不等于每个模型调用成功。
6. 用最小授权请求验证模型实际返回、文件/命令、网页检索、图像读取和浏览器。按实际模型和来源记录失败，禁止把缓存名称当调用成功。不要故意耗尽额度。
7. 向工作台大管家提交教程里的小网页任务，按原生流程到技术审核、实际体验和待用户验收。不能由维护Agent替各Bot完成业务后声称全自动。
8. 核对手动模型选择不被覆盖、13点timer时区、观察器输出、忙碌停机保护和重启后不重复派单。未自然等待定时触发的检查标注为配置/手动测试，不写已验全天运行。
9. 给用户工作台地址、知识库目录、实际截图、通过/受阻清单及下一步。最终验收仍由用户确认。

维护边界：优先复用当前七角色和已启用技能；候选技能不擅自启用。Bot文件/命令Full设置不代表拥有操作系统隔离或原生新Full任务授权。普通项目单主编码，方案最多两轮、技术/体验共用最多两轮。停止后恢复须核对旧回执。默认模型和当前任务选择分开，跨运行时新会话读取交接。

迁移对象是工具、流程和可读记录；不承诺原Mac会话、派单链和上下文无损恢复。需要续办旧项目时，用户明确指定后另建本机会话读交接。保留旧账本，禁止用空壳记录冒充成功。
