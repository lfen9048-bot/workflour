# 记录约定

## 这是什么

这是你我搭建多 Agent 协作开发工作流的共同工作记录。保留可复用的结论、实际操作和判断依据，让下一次对话能接着工作。

## 事实与想法怎么区分

- **用户已明确**：记录用户表达的需求或选择，注明日期与来源；必要时保留短原话。
- **共同决定**：记录已在对话中达成的选择，注明依据与确认来源。
- **助手建议**：作为可讨论方案，不改写成用户要求。
- **工作假设**：注明假设理由、影响和待核实点。
- **待定**：允许以后随构建逐步明确；不因此要求用户先填完一份完整问卷。

执行状态另行记录为：计划、进行中、已执行、未验证、已验证。文件已生成、命令已运行、测试已通过是不同事实。

## 有实质进展时如何更新

2026-11-05，用户明确同意：有实质进展时再更新 Obsidian。重要结论、实际产物、验证结果和关键交接属于实质进展；零散讨论不必逐条记录。具体约定见 [06-决策/0001-项目入口与上下文记录约定](06-%E5%86%B3%E7%AD%96/0001-%E9%A1%B9%E7%9B%AE%E5%85%A5%E5%8F%A3%E4%B8%8E%E4%B8%8A%E4%B8%8B%E6%96%87%E8%AE%B0%E5%BD%95%E7%BA%A6%E5%AE%9A.md)。

1. 在 `04-搭建/` 新建或追加当日记录，写清目的、实际操作、结果、问题和下一步。关键命令注明目录、版本与必要环境信息。
2. 有实际调研时，将来源链接、查阅日期、适配点、许可证与维护核对情况记入 `02-调研/`；未核实字段明确标注。
3. 形成工作流草案时，放入 `03-设计/`，关联需求与依据，并标明草案状态。
4. 有重要选择时写入 `06-决策/`，保留候选、理由、代价和确认来源；后续推翻时链接新决策，保留历史。
5. 有验证时写入 `05-验证/`，记录预期、实际结果与证据；未运行的检查不能写成通过。
6. 更新 [首页](%E9%A6%96%E9%A1%B5.md) 的当前状态和会话交接；只在得到新信息时更新 [01-需求/目标与待定事项](01-%E9%9C%80%E6%B1%82/%E7%9B%AE%E6%A0%87%E4%B8%8E%E5%BE%85%E5%AE%9A%E4%BA%8B%E9%A1%B9.md)。

## 内容与文件习惯

- 日期采用 `YYYY-MM-DD`，记录时间采用 Asia/Shanghai。
- 内部引用使用 Obsidian 双向链接，外部引用保留原网页链接和查阅日期。
- 同一天可以追加多次工作；互不相关的搭建事项单独建文件。
- 新建分区里的第一篇笔记时，从首页加上实际链接；空目录不创建占位笔记。
- 记录必要摘要和证据位置，不机械复制整个聊天或全部终端输出。
- 配置记录使用变量名或已脱敏内容，凭据正文不写入笔记。
- 搭建/决策笔记仍随实质进展人工维护。2026-11-10 起，已注册项目由本机观察器自动更新 `07-自动记录/` 中的进度、角色可见记录、证据链接和异常；不覆盖其他手写笔记，不以自动摘要代替原始证据。
