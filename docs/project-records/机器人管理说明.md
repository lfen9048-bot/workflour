# 机器人管理说明

## 现在的两层管理

**你 → 大管家 → Code Team · 总控 → 5个专业成员。**

- **大管家**是日常主入口，默认DeepSeek V4.1 Flash＋Low：接需求、找团队、转交和汇报，不做技术方案、不直接派五个成员。
- **Code Team · 总控**是原来的“项目总控”，Bot ID和原有任务不变：管理具体代码项目，组织规划、实施、独立审核与测试。它的模型仍保持用户选择的DeepSeek V4.1 Flash＋Max。
- **方案主持**负责方案收敛和接口细节；风险规划、主力编码、协作编码、独立审核分别承担已有职责。
- **通用助手**仍是临时讨论和管理设置的备用入口。

新项目可直接对大管家说：“交给Code Team做一个……，项目目录……，验收标准……。”大管家只转给Code Team总控，总控再安排成员；最终由你验收。

原来直接交给Code Team总控的项目，继续在原对话处理，不要求重建。询问进度不会重新派单。新项目若缺少关键目标，由大管家或团队总控简短澄清；不能擅自把猜测当作已确认需求。

正式团队共8个Bot（大管家＋Code Team总控＋5成员＋通用助手）均设工作台Full。7个DSH角色的新原生会话也改为danger-full-access／never并读回验证；Antigravity按工作台Full运行。既有DSH原生会话保留自己已保存的沙箱设置，不能声称它们已被批量迁移；工作台Full可批准其支持的原生提权请求。之前被用户停止的权限探针未继续。

日常操作从[机器人工作台](http://127.0.0.1:8799/)开始。你负责说清需求、处理必要审批、决定是否验收；项目总控负责创建项目、组织成员、执行命令和维护交接。

**当前权限更新（2026-11-10）**：按用户要求，总控、5个Code Team成员和通用助手默认及已有对话均设为Full access。下面“先问我”的截图展示的是此前状态；改变权限的方法仍可参考。详见[04-搭建/2026-11-10-全权限与总控派单调整](04-%E6%90%AD%E5%BB%BA/2026-11-10-%E5%85%A8%E6%9D%83%E9%99%90%E4%B8%8E%E6%80%BB%E6%8E%A7%E6%B4%BE%E5%8D%95%E8%B0%83%E6%95%B4.md)。

本说明附有 2026 年 11 月 10 日从你的工作台和 Obsidian 实际截取的 8 张原始图片。浏览器开启了翻译，所以图里 High 可能显示为“高的”，Max 显示为“最大限度”；这些是同一选项的显示翻译。截图里的任务状态只代表拍摄当时。

## 1 先分清机器人 对话和项目

| 名称 | 你可以怎样理解 | 什么时候新建 |
| --- | --- | --- |
| 机器人 Bot | 一个长期保留职责、模型设置和技能的成员 | 确实需要增加一个独立角色时 |
| 对话或任务 | 这个成员处理某一件事的工作记录 | 换项目、开始独立的新任务时 |
| 项目目录 | 代码、需求、计划和共享交接的存放位置 | 开始一个新的代码项目时 |
| 部门 | 左侧整理机器人的分组 | 机器人多了，需要分类时 |

**新项目通常只需要新对话，不需要复制整套机器人。** 同一套规划、编码、审核成员可以继续使用，由总控为它们建立本任务的独立会话。

新对话不会删除旧记录，也不等于清空机器人长期记忆。项目目录要明确写出，并由总控核对实际执行目录。

群组聊天用于看讨论和公告。普通群消息不一定会启动成员；正式派工仍交给总控。

## 3 新开任务与找回历史

*图2 总控资料中的新对话和历史列表：历史截图保留本机；请参照[当前工作台与安全模型卡](../evidence/2026-11-11/README.md)。*

图 2：点聊天顶部的“项目总控”，右侧出现资料面板。“新对话”在模型栏下方，下面就是历史任务列表。

1. 在左侧选中要使用的机器人。
2. 点聊天顶部的机器人名字，打开右侧资料面板。
3. 点“新对话”，开始一个独立任务；要继续旧任务，就点下方对应的历史记录。
4. 第一条消息写清项目名称、完整目录和任务目标。

**继续未完成任务，优先回原对话；新项目优先开新对话。** 不要因为机器人暂时没回复，就再开一条对话重复交同一个任务。

推荐使用可读的标题，例如“总控 · 待办网页 · 第一版”“审核 · TODO-001 · 首轮”。标题便于寻找，真正的执行位置仍以项目目录和交接为准。

## 4 让总控创建项目并开始工作

不需要你打开终端初始化。下面的话发给总控即可；方括号内容换成你的实际需求。

```text
请创建一个新项目，名称是 [项目名称]。
项目目录是 [完整目录]。

请使用现有 code-team 模板初始化。
如果目录已有文件，不要覆盖，先说明现状。
请核对本次任务的实际执行目录，建立交接和 Obsidian 自动记录。

目标：[要做什么]
验收条件：[列出可以实际检查的结果]
本次不做：[范围之外的内容]

请组织规划、分工编码、独立审核和真实测试。
范围内自动推进，需求不清楚时再问我。
完成后给我启动方法和验收清单，停在待我验收。
```

目录创建成功，不代表旧会话的默认工作目录也已经改变。若总控提示仍在旧工作区，应让它处理正确目录的新任务与交接；必要的目录权限由你针对具体请求批准。不要把聊天里出现了新路径，当成已完成目录切换。

当前初始化模板支持新目录或空目录。已有代码仓库应先让总控检查接入方式，不能直接覆盖初始化。

## 5 修改名称 分组和收起旧机器人

*图3 机器人操作菜单：历史截图保留本机；请参照[当前工作台与安全模型卡](../evidence/2026-11-11/README.md)。*

图 3：这是“通用助手”的真实操作菜单。鼠标移到左侧机器人条目，打开该条目的操作菜单，可以看到这些管理项。

| 操作 | 用途 |
| --- | --- |
| 置顶 | 把常用成员放在容易找到的位置 |
| 移至部门 | 调整左侧分组；只整理显示，不自动改变职责或协作流程 |
| 标记为未读 | 留一个稍后回看的提醒 |
| 新建对话 | 给同一个机器人新开任务 |
| 重命名 | 修改显示名称；不会因此更换模型或重写技能 |
| 归档 | 将暂时不用的成员收起，整理前先确认没有任务仍在运行 |
| 删除 | 移除机器人；不要把它当成普通的清理或停止按钮 |

可以沿用现有“总控、Code 团队、通用助手、历史与验证”分组。名字建议写职责，把当前模型放在模型设置里管理。

新增成员的入口在左上角“＋”里的“新建机器人”。普通项目开工不需要点这里。新建普通机器人也不会自动加入既有 code-team 编排；增加正式角色时，还需要配好职责、模型和流程归属。

## 6 修改职责与操作审批

*图4 机器人设置中的职责和审批：历史截图保留本机；请参照[当前工作台与安全模型卡](../evidence/2026-11-11/README.md)。*

图 4：打开机器人资料后，点右上角齿轮进入“机器人设置”。这里能看到“指示”“先问我／直接执行”和“备用 AI”等选项。

- **指示**：这个机器人长期应该怎样工作。临时任务要求放在聊天里；调整长期职责时再修改它。
- **职务**：展示给你看的角色说明。只改这段介绍，不会自动改好背后的技能和派工规则。
- **先问我**：操作前可能弹出具体审批卡。
- **直接执行**：会减少操作确认，属于权限行为变化，不是提速或切模型按钮。
- **备用 AI**：与手动选模型是另一套机制。需要明确控制实际模型时，先了解备用接管规则再配置。

正式流程成员已有协调、编码或审核技能。仅修改名字或一段介绍，不等于完整地改好了它的职责。较大的分工调整交给总控说明影响并统一维护。

## 7 换模型与思考程度

*图5 真实模型目录：历史截图保留本机；请参照[当前工作台与安全模型卡](../evidence/2026-11-11/README.md)。*

图 5：聊天右上角的模型名称可以展开目录；“显示全部模型”能展开更多选项。模型可能来自 DeepSeek、WorkBuddy、WorkBuddy Global 或 Antigravity，选择时要一起核对来源。

*图6 当前模型的真实思考档位：历史截图保留本机；请参照[当前工作台与安全模型卡](../evidence/2026-11-11/README.md)。*

图 6：拍摄时，这个模型显示 Low、High、Max 三个档位，浏览器分别译为“低的、高的、最大限度”。其他模型可能提供不同档位，不能照搬。

**需要只改当前任务时，使用总控或通用助手提供的模型设置卡。** 本版本原生顶部思考菜单会影响 Bot 默认设置，因此图 5、图 6 用于认入口与看目录，不能据此认为每次直接点击都只改当前对话。

操作顺序：

1. 让目标任务先结束当前回合，或明确停止；运行中不能强行换模型。
2. 修改普通成员或通用助手时，找项目总控；修改项目总控时，等总控空闲后找通用助手。
3. 明确机器人、任务和生效范围，请它打开设置卡。
4. 选已接入的模型、该模型实际支持的思考档位，核对“仅当前任务”或“设为默认”。
5. 应用后看回读结果：机器人、任务、模型来源、思考档位、生效范围是否都正确。

只改当前任务可以这样说：

> 打开模型设置。我要修改 [机器人名称] 的 [任务名称]，只改这一个任务，不改默认。先确认它空闲，再显示可用模型和真实思考档位。

修改以后新任务的默认值可以这样说：

> 将 [机器人名称] 的默认模型设为 [模型与来源]，思考档位为 [实际支持档位]。这是修改以后新任务的默认值，请说明对现有任务的影响，不要顺便改其他任务。

从 DSH 切到 Antigravity，或反向切换时，现有安全流程会创建新任务并读取项目交接，保留旧会话。模型目录里有名字，不等于这一轮已经成功调用；应以切换回执和后续实际运行结果为准。

## 8 看进度 处理审批和停止续跑

*图7 真实等待审批与停止按钮：历史截图保留本机；请参照[当前工作台与安全模型卡](../evidence/2026-11-11/README.md)。*

图 7：左侧黄色标记提示有事项等待处理；聊天底部是审批卡，包含“始终允许、拒绝、允许一次”；最右下方方块是“停止本轮”。截图中没有替你批准这次请求。

想看进度，直接问总控：

> 请核对当前项目进度，告诉我当前阶段、负责人、等待原因和下一步。只查看现有任务，不要重新派单。

| 看到的状态 | 怎么处理 |
| --- | --- |
| 工作中／正在思考 | 看最后活动与负责人，等待结果 |
| 等待模型回复 | 请求可能还开着；让总控核对，不要反复提交同一任务 |
| 等待审批 | 展开“详情”，核对具体目录、文件或命令，再决定允许或拒绝 |
| 失败／已停止 | 先查旧派单及已经产生的修改，再决定继续 |
| 待验收 | 获取启动方法，按需求亲自试用 |

审批有时在成员自己的任务里。收件箱和总控提示能帮助找到它。遇到只显示“tool／工具”的卡片，先展开详情；不要只凭这个泛称判断操作。

**停止本轮不等于回滚文件，也不能直接认定所有已派出的成员都停止了。** 要停整个项目，应明确告诉总控暂停项目、逐个核对已派任务，并向你报告哪些已经停止、哪些仍在运行。

明确继续时，在原总控对话里说：

> 继续这个项目。先核对旧派单、已修改的文件和测试，完成的不要重做。确认失败或停止的步骤后再安全重试，保留旧记录。

同一步恢复重试有次数限制，超过限制应由总控解释原因并交给你决定。不要删除账本来绕过限制，也不要反复新开任务重发需求。

## 9 在 Obsidian 看项目和成员记录

*图8 Obsidian 自动项目首页：历史截图保留本机；请参照[当前工作台与安全模型卡](../evidence/2026-11-11/README.md)。*

图 8：这是已经跑过完整流程的 recovery-flow-demo 项目，用来展示记录入口；它不是新待办网页的完成证明。

从知识库 [首页](%E9%A6%96%E9%A1%B5.md) 进入 工作流自动记录（本机附件或自动记录，未上传），再打开对应项目。

- “进度”看当前阶段、负责人和下一步。
- “异常”看审批、失败、停止或同步问题。
- “角色会话”查看各成员独立工作记录，旧尝试也保留。
- “材料与测试证据”打开需求、计划、审核结论、测试输出和验收材料。

总控登记项目后，后台约每 20 秒检查更新一次。Mac 需要登录并运行服务；长记录或休眠会延迟。自动目录由程序维护，你自己的补充笔记放在自动目录外。

DSH 桌面的“工作区”按真实目录组织会话；工作台的“部门”按机器人组织成员，两者用途不同。本工作流的 DSH 自动分类范围目前限于 workflour 目录及其真实子目录，不能假定任意外部目录都会自动归组。

## 10 验收和下一轮任务

总控交付后，先让它给出可执行的启动方法和逐条验收步骤。你实际检查功能，再决定是否接受。

通过时说：

> 我已按清单实际检查，[任务编号] 当前版本满足要求，验收通过。请记录我这条确认、对应代码版本和交接。

未通过时说：

> [任务编号] 暂不通过。复现步骤是 [具体操作]，预期是 [结果]，实际是 [问题]。请修复后重新审核、测试，再交给我验收。

同一项目的新功能继续使用原目录，并让总控为新任务读取共享交接、保留上一轮记录。换成另一个项目时，重新写清目录与目标。机器人职责可以复用，项目之间的交接不能靠猜测。
