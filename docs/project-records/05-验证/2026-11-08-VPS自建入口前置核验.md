# VPS 自建入口前置核验

## 本轮范围

用户说明拟用现有 VPS 为 Mac 上的 OpenMausBot 提供公网 HTTPS 入口，并要求验证。本轮执行前置核验，没有部署或开放公网入口，也没有发送模型消息、生成手机配对邀请。

## 现状恢复

- 项目：`<WORKFLOUR_ROOT>`，沿用同一 `~/.openmausbot` 数据目录。
- 固定版本：npm 缓存中的 `openmausbot@0.1.143`；不是未安装应用。此前仅在 `/Applications` 查不到桌面 App 不能说明未安装。
- 核验开始时，8799 没有监听，也没有 OpenMausBot 进程；旧记录中的本地 UI 成功属于此前那次运行。

## 实际操作与结果（22:06，Asia/Shanghai）

以已有 Node 和缓存 CLI 临时执行 `serve --no-pair`，本地端口就绪后：

| 检查 | 结果 |
| --- | --- |
| `/api/health` | 200，应用为 openmausbot |
| `/.well-known/openmausbot/environment` | 200，版本 0.1.143 |
| 本机 owner 的 `GET /api/bots` | 200；Doc、Coder、MausBot 共 3 个 Bot |
| 公网 Host、无配对会话访问 `/api/bots` | 403 |
| 公网 Host + X-Forwarded-For / X-Forwarded-Proto | 403 |
| 伪装 localhost Host、同时带代理转发头 | 403 |

未向任意 Bot 发 prompt。完成后仅停止本轮创建的进程组，8799 恢复未监听状态。OpenMausBot config.json 前后 SHA-256 一致；没有修改现有启动脚本、Bot 或模型配置。

通过已有 SSH 密钥与严格主机指纹检查，只读核对 VPS：

- `your-public-host.example` 的真实 A 记录为 `<YOUR_VPS_IP>`。Mac 系统解析由 Clash 返回 Fake-IP，不能直接把该内部地址当成权威 A 记录；已另从核心和 VPS 的真实解析核对。
- SSH TCP 22、Xray TCP 443、sing-box UDP 8443 正常监听。
- TCP 80、8080、9001 没有监听，VPS 本机连接这些端口也未成功；它们仅为候选端口，尚未验证公网防火墙放行。
- 没有创建 SSH 反向隧道或启动 Caddy/Nginx。

## 结论与未验证项

本机服务、已有 Bot 和未配对请求拒绝行为通过；域名解析与现有 VPS 服务通过检查。这是入口部署前置条件核验，不是手机端到端验收。

尚未验证：HTTPS 证书签发、8080 公网可达、SSH 9001→Mac8799 转发、`--public-url` 下完整配对会话、SSE/重连、手机蜂窝网络访问。官方托管隧道容量满的说法来自用户提供背景，本轮未重新验证其容量或账号状态。

下一步可准备独立的 VPS HTTPS/反向隧道方案，继续保留 443/8443 代理服务。公共入口必须沿用远程配对认证与正确 Host/转发头；不要据本轮 403 样本直接宣称所有 API、WebSocket 或旧版本均已安全验收。公网部署与用户手机配对留待下一阶段。
