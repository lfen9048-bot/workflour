# 功能盘点与剩余缺口

用户要求详细解释当前完成内容及缺陷。本轮只读核对实现、验证记录和运行状态，未修改代码、模型或服务；此笔记补充交接，不把发现问题当作已修复。

## 已验证的完成范围

DSH项目总控自主完成7次worker委派、小功能、GLM审核和65项测试，停在用户验收。模型设置卡片、助手设置idle总控、DSH/AGY模型档位与跨运行时新任务交接有真实验证。工具包78项Python、3份Node测试文件通过。DSH历史7工作区、66新增归属、42改名、11CAPTURE归档及新会话实时显示通过。本次复查本机/公网正常，13个Bot均idle，唯一主Bot为项目总控。

## 实际缺口，尚未修复

1. **失败/停止/未绑定claim缺少安全续试入口**：`scripts/coordinator-workflow.py`只有claim、receipt、result、advance、rework，没有retry/reconcile/reopen。已settled失败/停止不能重claim，新任务归档又只允许已完成verify。技能的“一次瞬态重试”没有完整工具对应；不能把防重派通过说成异常续跑完整。
2. **新模板仍有旧总控角色**：`scripts/new-project.py:101`仍写owner=Codex；`templates/project/PROJECT-WORKFLOW.md:25/30/41`仍要求当前Codex窗口协调，与日常DSH总控不一致。
3. **已有仓库接入未成型**：初始化器只接受新/空目录。真实已有仓库的增量接入、构建依赖、数据库、Git冲突、多并行功能尚未完整演练。
4. **Obsidian不是自动聊天镜像**：当前知识库入口和进度笔记已维护，各角色原始记录在OMB/对应运行时，项目有材料与导出工具；没有保证每个新项目、每轮对话均自动导出并更新Obsidian的持续链路。
5. **自动分类告警不足**：队列写失败被catch，消费者失败保留重试但无用户告警；大规模/长期/磁盘异常未压测。自动归组限定本仓库真实子目录，外部新项目不自动纳入。

## 需要保留的边界

- 由模型协调并调用检查工具，不是每个动作都有独立硬状态机。派单claim、实际发送和保存回执非跨系统原子事务，异常时需要核对。材料一致不等于需求正确或测试完整。
- role/actor是防误用规则，不是身份认证或文件沙箱；所有Agent仍共享当前用户的磁盘权限。新会话不等于清除全部长期记忆和历史召回。
- 仅验证空闲检查点后的接手，不覆盖写文件中宕机、全部运行中委派恢复、整机休眠/重启。实际操作审批仍需人处理。
- 原生顶部思考菜单仍会改Bot默认，跨运行时原生菜单不强制新任务；安全行为由模型设置卡片/工具提供。目标忙时不能切换，改总控自己由助手办理。
- 目录列出不证明所有供应商均有权限/额度，也没有比较全部模型的编程/规划能力。GLM Low总控只验证配置与READY，不证明完整编排同样有效。
- DSH不是全部运行时历史统一库：Antigravity原始聊天不进入DSH侧栏；统一查看仍以OMB及项目/Obsidian索引为主。DSH当前是项目工作区加角色标题，不是三层嵌套标签系统。
- 标题与自动归组仅针对真正有首条工作消息的会话；空协议探针可能保留未命名。桌面关闭时排队下次消费。
- undo保留了清单和私有备份，并做原生服务mock检查；未在生产历史上执行完整回滚，且执行前须核对整理后的人工修改。

## 建议顺序

先补失败/停止后的续试与对账，再统一新项目模板和已有仓库接入；然后建立Obsidian自动索引/导出和可见的异常状态。后续再扩大真实项目与跨模型组合测试。报告Agent依照用户要求继续暂缓。
