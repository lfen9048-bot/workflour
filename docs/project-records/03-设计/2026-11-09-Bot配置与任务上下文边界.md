# Bot配置与任务上下文边界

用户询问：Bot预先固化后，开始新编程任务并重置上下文会怎样。本轮只读核对当前配置和OpenMausBot0.1.143安装源码；未创建/重置任务，未更改记忆策略。

## 当前事实

- 固定能力：DeepSeek编码profile选择WorkBuddy/deepseek-v4.1-flash及通用code-collaboration技能；persona要求按项目任务和交接工作。未把演练Bug写入通用profile/skill。
- 项目内容：演练目录的AGENTS.md、README、交接文件及群公告保存本次任务和临时分工。DeepSeek默认cwd及演练群cwd仍指向discussion-demo。
- 新私聊任务生成新threadId和空resumeCursors；群新任务也有新threadId，不直接拼旧群全文。模型/技能/固定说明及默认目录不会因此清除。
- 新线程不等于完全无旧背景：私聊还会收到Recent work、长期memory和team/section context，普通用户发起的私聊可自动检索旧会话片段；autoRecall默认开启。群禁止自动带入旧私聊片段，但仍可带记忆笔记。仅关闭memory也不能据此承诺全部来源隔离。
- 两个参与Bot当前memory索引均为初始模板、无主题笔记；这不代表无历史检索能力。
- compact是总结或重建当前上下文，不是清除所有历史。未发现可以笼统称为“一键彻底清空”的入口。

## 建议，尚未作为新功能实施

同一项目的新任务：新开任务，重新读取项目需求与交接，只带必要背景。全新项目：独立目录和项目群/任务、正确公告、明确记忆与历史召回策略。复用通用岗位能力，任务分工按项目指定。

严格跨项目隔离和重置后的上下文来源验证仍待实施/实测；本轮没有自动修改全局记忆开关，也没有清除已有记录。

## 核对依据

- 项目：`integrations/openmausbot/profiles/deepseek-coder.patch.yml`、`agents/deepseek-coder/skills/code-collaboration/SKILL.md`、`examples/discussion-demo/AGENTS.md`。
- 安装源码根：`/opt/homebrew/lib/node_modules/openmausbot/dist-server/server/`。`store.js:2208`新私聊任务、`:924`新群线程；`index.js:1118`自动召回、`:8510`起私聊上下文、`:10470`群召回边界；`config.js:530`默认开关；`routes/bot-messages.js:365`及`routes/channels.js:494`压缩。
- 只读API：Bot的模型、cwd、soul，演练群公告与cwd，两个Bot的memory索引及主题数量。
