# 手动多Agent完整项目流程

## 当前授权和默认安排

用户已授权搭完整项目协作流程。延续首轮手动接力；本轮默认Coder做计划/实现/修复、Gemini独立审查、Doc写文档、协调者核对实际测试与组织交接、用户最终验收。角色可调整，不把实施默认写成用户永久决定。

流程：需求和验收条件 → 计划/任务 → 实现 → 独立审查 → 测试验证 → 文档 → 用户验收。任何失败回到对应阶段；改代码后旧审查/测试失效。

## 已实现的项目入口

`python3 scripts/new-project.py <新目录或空目录> [--name 名称] [--git]`。默认不建Git、不发模型请求、不改profiles。新项目有Spec Kit中立脚手架、PROJECT-WORKFLOW.md、AGENTS.md、七阶段提示词和交接材料。

项目内`.workflour/handoff.json`为持久任务记录，含需求、阶段、负责人/下一负责人、产物、代码/基线、审查和测试记录、决定、阻塞、下一项动作。`HANDOFF.md`从JSON生成。

`python3 .workflour/check.py check [--stage 阶段]`核对材料；`snapshot`输出代码哈希；`test -- 可执行文件 参数...`无shell实际执行并保存退出码/证据；`handoff`生成交接。

## 检查边界

- implementation_owner和reviewer必须不同；未处理问题不能进入验收。
- 代码快照需同时对应审查和有效测试；代码改动使旧结果过期。
- 失败历史保留，同一命令在当前快照下成功重跑可覆盖失败结论。
- 当前及历史证据哈希都核验；文件锁和旧版本检查防多写者覆盖。
- 路径限定项目内，拒绝目录外symlink/绝对/父级路径；这不是Agent系统权限沙箱。
- acceptance表示等待用户验收；done须有明确用户确认记录并绑定代码快照。检查器只核材料一致性，不能验证真人身份或完整覆盖率。
- 同一Agent优先原生恢复；跨Agent和真正新会话以项目文件交接，不依赖聊天自动同步。

## 实际演练

独立目录`examples/workflow-demo/`，从原文本统计例子复制代码，演练添加可选--words，保持默认JSON兼容。此为协作流程技术演练，不代表用户最终产品/技术栈选择。三个角色在OpenMausBot各有该目录的新任务，旧聊天/默认profiles保留。

实际演练已完成需求、计划、实现、独立审查、真实返工、复核、独立测试、文档和逐FR验收材料。Gemini首次发现R1-R3后退回Coder；先补用例得到17项中3失败，修复后18项全过，Gemini重新读取修改后的文件并全部verified，协调者再次独立执行18项全过。Doc实测示例并写README/docs。最终阶段为acceptance、用户确认pending，done按预期被拦截。

演练还修正了两个使用规则：stage表示正在做的阶段，开工前检查上一已完成阶段，完成后再检查当前阶段；baseline采集实现前的真实值，删除文件保留code_files条目且当前快照为null，不能把baseline改成修复后的值。
