# 项目入口与上下文记录约定

## 背景

当前项目目录 `<WORKFLOUR_ROOT>` 是后续搭建多 Agent 协作开发工作流的地方。需要让新接手的 AI 找到既有上下文，并继续实际工作。

## 共同决定

- 在项目根目录建立 `AGENTS.md`，保存项目用途、知识库位置、接手阅读顺序和稳定协作规则。
- Obsidian 知识库是需求、调研、讨论、决策、工作日志和当前进度的集中记录处。
- 代码、脚本、配置和测试保存在项目目录；记录关联实际文件、命令结果或提交。
- 进度和待办统一维护在 Obsidian，不在项目入口里复制一份动态状态。
- 有实质进展时更新相关笔记和首页交接；重要结论和关键交接属于实质进展，零散讨论不逐条记录。
- 接手者先阅读首页、需求页和记录约定，再按首页链接查阅相关日志与有效决策，并检查项目实际状态。

## 确认来源

2026-11-05，用户在本次对话中明确：

> 可以，就按这版写到当前项目的 AGENTS.md，有实质进展时再更新 Obsidian，把这次约定也记进去。

## 取舍与适用边界

稳定入口与动态记录分别维护，可减少重复状态发生分歧。知识库使用本机绝对路径；更换机器或路径时需更新入口。接手工具必须能够读取项目说明和对应本地文件，无法读取时应明确缺失的上下文。

项目类型、工具、模型和 Agent 分工仍待后续逐步确定。本记录不代表已经选择或实现编码工作流。
