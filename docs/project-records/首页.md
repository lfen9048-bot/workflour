### 端口选择的硬约束（重要）

VPS 的 **443 被 xray 的 VLESS+REALITY 独占且无 fallback**，REALITY 会把非 VLESS 流量伪装转发到 `www.postgresql.org:443`。抢 443 会打断正在用的代理，所以 HTTPS 走 **TCP 8443**（已实测公网放行），证书验证走 80。

UDP 8443 是 sing-box，所以 Caddy 关掉了 HTTP/3，只用 h1/h2。

### 四个必须知道的踩坑

1. Caddy 默认开 HTTP/3（UDP 8443），撞 sing-box 导致启动失败 → `servers { protocols h1 h2 }`。
2. `nc -z` 探测端口不可信：本机 Clash TUN 会对不可路由地址也报"可达"，必须用 `curl --noproxy '*'`。
3. 历史上 `nohup` 隧道会被会话回收，裸SSH也曾断开；先用循环重连，现已进一步改为 **launchd 独立托管服务和SSH**，不再依赖shell守护循环。崩溃恢复、主动停止已实测通过。
4. 历史上pidfile缺失会导致重复建链；现由launchd精确label判断托管任务，并校验旧SSH是否冲突，pidfile只供兼容参考，不参与停止或归属判断。

### 三个必须知道的实现差异

1. `run-acp-agent.sh` 额外支持 `--version`：customAcp 驱动用它做安装探测，不支持就显示 unavailable。
2. 两个 ACP patch 都 `disabled: true` 了 `llm-deepseek-account`：它会 `console.info` 写 stdout，污染 ACP 协议流。属配置层修复，不是丢弃协议行。
3. 先前通用customAcp的load/resume差异已由项目内薄桥接解决：现在恢复同一个Harness原生session，Coder/Doc均通过工具专属随机值恢复验收。`recoveryText`仅为原生恢复不可用时的上层兼容路径，跨Agent仍靠项目交接文件。
