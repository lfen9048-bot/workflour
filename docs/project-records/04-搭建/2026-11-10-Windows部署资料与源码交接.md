# Windows 部署资料与源码交接

## 用户目标

用户希望在 Windows 上按同样方法部署 workflour，要求详细列出项目 Markdown 和工作方向，并写清 Agent 下载、WorkBuddy 插件安装、逐步部署方法。本轮完成部署资料和可转交源码，不把资料完成写成 Windows 部署完成。

## 已完成

- 阅读当前实现与最新两层管理记录，目标为大管家 → Code Team总控 → 五成员，另加通用助手，共8 Bot、7个DSH profile和独立AGY。
- 使用 search-first，核对 DSH 官方 Windows 安装包、桌面CLI注册、WorkBuddy官方Windows安装及插件5.13.1上游文档、AGY官方PowerShell安装、OMB0.1.143/Node要求；文件锁候选Portalocker、后台复用Windows Task Scheduler。
- 写成10份部署文档和1份部署登记JSON模板，覆盖软件下载/登录、Bot职责、路径/profile/权限、模型设置、额度备用、续跑、新项目、Obsidian、后台与验收。
- 枚举整理前项目Markdown 281份：44份核心原文随包，其余237份旧项目/证据逐项索引；本次部署文档另外随包。
- ZIP包含136个源码/模板/测试/文档文件，以及manifest和只读校验器。未包含运行账户目录、数据库、node_modules、实际公网Caddy配置或当前产品项目内容。

## 发现的 Windows 必改项

- Mac启动脚本/固定应用路径，ACP的Windows .cmd、编码、子进程与停止语义。
- setup依赖旧Doc登录配置和Unix node_modules软链接，Windows首次安装必须从本机登录bootstrap。
- fcntl锁、O_NOFOLLOW、原子替换、项目复制的check.py，以及后台launchd。
- bot-model.py靠.sh名称识别运行时；改Windows入口必须同步调整。
- skills中的Mac绝对路径、旧Bot UUID；observer默认VAULT与桌面分类的Electron路径。
- 模板中SpecKit的Bash脚本不能直接作为PowerShell调用。

## 本次验证

- 自编文档相对Markdown链接23处均存在，部署JSON可解析。
- ZIP CRC及136个清单SHA-256核对通过。
- 临时解压后校验器通过；修改副本JSON后校验器正确拒绝。
- 打包候选文件凭据模式扫描无命中；这是模式检查，非绝对无敏感信息证明。运行凭据目录从未纳入候选。
- **未在Windows安装、未实现Windows启动器/后台管理器、未跑Windows端到端验证**。现有Mac运行Bot/配置未改。
