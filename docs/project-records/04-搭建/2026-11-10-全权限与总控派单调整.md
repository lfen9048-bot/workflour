# 全权限与总控派单职责调整

用户明确要求“我要给他们全部权限”，并指出总控应尽快下发任务、具体方案由方案提出者负责。本轮按正式团队7个Bot执行：项目总控、5个Code Team成员、通用助手；历史测试Bot不扩大权限。

## 已执行

通过原生 PATCH /api/bots/{id} 设置 approvalMode=full、applyToAllThreads=true。7个默认值与当时38个已有对话读回为full，包含正在进行的项目；模型与思考档位未改，不中断项目、不重复派工。新增独立权限探针对话另计。Full是工作台工具审批级别，不代表新增macOS系统权限、联网账户或任意发布授权。

更新agents/coordinator/skills/coordinator-workflow/SKILL.md及总控原生soul，保留安全续跑、回执、复审和用户验收规则：
- 总控仅做最小需求核对、派单、跟踪和证据检查，不代写详细技术方案。
- 三方提案冲突交方案主持决定；总控不先定接口再让方案主持誊写。
- 常规启动争取3轮以内成批工具核对后派单；遇真实阻塞说明原因，不能牺牲安全回执。
- 新项目命令必须显式带--workflow code-team；不因目录权限问题偷偷改成旧演练子目录。
- 不无故扫描旧项目、UI组件或运行时源码；已授权Full的范围内本地操作不再额外口头请批。
- 用户原话与助手假设分开，核心产品含义不清时先用一句问题澄清。

本轮沿用已有search-first调研及原生权限、配置机制，无新增框架。
