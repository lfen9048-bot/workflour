# 免费、临期额度优先与 13 点签到恢复

## 用户要求与当前结果

用户要求走 DeepSeek 的 Bot 先用国际版免费额度，国内两个已勾选账号按插件规则使用；免费耗尽后，国际版和国内版快过期的额度优先。随后明确“换模型和签到都改成每天13点”。当前每日签到和模型恢复边界均为 **北京时间 13:00**，替代原 08:00 约定。执行中的模型请求不被打断，恢复在下一新回合发生。

六个新 DSH profile 已加载此规则，角色默认模型不变；Gemini/Antigravity 保持独立，不自动跨运行时备用。国内两账号沿用桌面插件池成员和区内顺序，不修改原 profile、不复制新凭据。当前国际账号池关闭，仅使用当前选中账号，不擅自启用其他账号。

实际优先顺序：**新鲜目录已核实的免费线路 → 国际/国内临期积分账号 → 其余 WorkBuddy 积分 → 用户已有 DeepSeek API**。同一区内保持插件原生池顺序，两个地区的临期队首按到期时间比较。临期按现插件三天阈值，月套餐不当作临期赠送。只能选择账号，不能控制上游具体扣哪个积分包。

默认 DeepSeek 初始只在同系列线路之间选择，只有明确额度错误才允许进入 GLM 等备用。Kimi/GLM 原角色模型先按用户配置调用；连接、排队和配置失败不直接当作额度不足转付费 API。目录或余额未知不当作耗尽。手动换 provider/model 优先；仅调思考档位保留实际新档位并继续同系列省额度策略。

## 实现与复用

复用本机 `dsh-connect-workbuddy` **5.13.1 / MIT** 的 CredentialStore、UpstreamClient、Catalog、Shim、Adapter；上游 [项目源码与说明](https://github.com/dingminhua/dsh-connect-workbuddy)。新增逻辑放在工作流目录，没有修改已安装插件包，也没有为签到升级插件。

- [budget-policy.mjs](../../../integrations/openmausbot/model-fallback/budget-policy.mjs)：免费促销有效性、五分钟快照、临期和账号顺序。
- [budget-router.mjs](../../../integrations/openmausbot/model-fallback/budget-router.mjs)：复用原生客户端读目录/余额，隔离各账号路由，校验账号和地区，内部路由不出现在手动模型菜单。
- [plugin.mjs](../../../integrations/openmausbot/model-fallback/plugin.mjs)：只续接失败的模型请求、保留手动设置、13 点换日、实际返回才确认成功。
- [client.mjs](../../../integrations/openmausbot/workbuddy/client.mjs)、[checkin.mjs](../../../integrations/openmausbot/workbuddy/checkin.mjs)：国内勾选账号签到，先查询、已签到跳过、请求后读回；超时未确认当天不盲目重领；跨进程锁防止重复。
- [workbuddy-pool-sync.rb](../../../scripts/workbuddy-pool-sync.rb)：新六 profile 的进程内私有完整配置覆盖，仅同步池偏好，源文件不写回。
- ACP 桥接保存模型/档位基线，重复同值 setter 不再误判成手动切换；真实成功变更才更新 revision。

自动化 `bot` 为 ACTIVE，每天 13:00 先签到再运行恢复状态检查。恢复逻辑在本地插件内，不依赖定时任务碰巧准点执行。定时签到仍依赖本机及 Codex 自动化可执行；本轮未等待次日 13 点验证调度器自然触发。尚无公开权威 task→native session 接口，原生同值选择与自动重复 setter 无法区分，因此没有猜测映射实现“点同一值强制重置”。
