## 日常使用的正式团队

正式代码项目使用 **项目总控＋5个Code Team成员**。用户主要给总控发需求、查看进度并验收；成员由总控按阶段调用，不要求用户逐个派单。

| 工作台名称 | 固定流程角色 | 职责 | 原界面名称 |
| --- | --- | --- | --- |
| 项目总控 | coordinator | 接需求、初始化项目、派单、跟踪、核对测试和交接 | 项目总控 |
| Code Team · 方案主持 | kimi | 独立规划并整合三方方案 | Code Team kimi |
| Code Team · 风险规划 | glm-plan | 检查需求遗漏、技术风险和可测试性 | Code Team glm-plan |
| Code Team · 主力编码 | agy | 主要实现、整合和测试 | Code Team agy |
| Code Team · 协作编码 | deepseek | 参与规划，承担独立代码或测试子任务 | Code Team deepseek |
| Code Team · 独立审核 | glm-review | 独立检查实际代码和测试证据 | Code Team glm-review |

流程为：总控接需求 → 三方规划（方案主持、风险规划、协作编码）→ 主力和协作编码按文件分工 → 独立审核 → 总控核对真实测试 → 用户验收。

模型设置保持原样，职责与模型分开。通用助手保留作临时讨论和管理空闲总控设置的备用入口；旧Bot保留在“90 历史与验证”，不需要日常逐个使用。旧记录和截图中的原名称仍有效。

2026-11-10整理只更新空闲成员的名称、说明和职责约定，没有改变模型、审批或旧任务目录。成员Bot的旧默认目录仍保留演练路径；新项目必须由总控在派单中明确绝对目录并核对实际执行位置，不能从旧默认目录猜项目。当前仍不承诺跨项目严格文件沙箱。
