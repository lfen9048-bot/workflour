# 安全续跑与自动记录实施

用户授权：修复失败/停止后的安全续跑、新项目模板，然后完善Obsidian自动记录和异常提示，实际完成一轮工作流验证。

## 已实施

- `scripts/coordinator-workflow.py` 增加绑定原生总控会话、UUID派单标记、只读reconcile、有证据且限一次的retry、原总控空闲后才能release-claim。回执校验来源/接收Bot/标记，旧尝试不能覆盖，旧失败/停止证据保留。
- `scripts/native_assignments.py` 使用OpenMausBot 0.1.143原生SQLite只读快照，按来源会话筛选，校验schema；无数据库修改或内部凭据借用。
- 修复 code-team 初始化owner、说明、初始交接，职责由DSH项目总控承担；manual默认兼容，新项目仍只限新/空目录，未引入已有仓库迁移。
- `scripts/workflow-observer.py` 登记明确项目，在本机launchd约20秒运行一次，只读同步项目进度、角色可见记录、证据链接、异常。写失败保留旧记录，错误/过时有提示；不派单或审批，不修改任务状态。
- DSH归组消费失败保留队列且输出诊断；入队失败不再完全吞错。已重新打开DSH桌面加载修改，实时诊断文件正常。
- 使用说明与总控/助手技能已更新：`integrations/openmausbot/RECOVERY-AND-RECORDS.md`、`USER-GUIDE.zh-CN.md`。

## 已观察的真实验证

- 独立新项目 `examples/recovery-flow-demo`，总控任务 `LOCAL-ID-001`。
- 总控原生派出三方规划；维护者仅停止DeepSeek第一次规划任务。原生状态cancelled/stopped；总控reconcile保存原回执，Obsidian自动显示停止提示。

## 选型依据与边界

复用现有账本、原生委派、可见会话导出器、本机launchd及Obsidian Markdown。参考 [Temporal重试策略](https://docs.temporal.io/encyclopedia/retry-policies) 的有限步骤重试原则，未引入额外调度服务或复制代码；[Obsidian官方存储说明](https://obsidian.md/help/data-storage)确认读取本地Markdown更新。无新增账号/订阅/依赖。

不声称任意外部副作用可回滚或进程级无损续接；本次受控停止证明原生任务停止和安全重新派单，不等于执行到一半的任意shell均已恢复。继续来源与actor标记不是身份认证，仍是共享文件协作。自动区之外搭建笔记仍人工维护，未添加报告Agent。
