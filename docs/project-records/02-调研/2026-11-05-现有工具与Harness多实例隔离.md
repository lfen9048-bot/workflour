## 上游能力与依据

查阅日期：2026-11-05。DeepSeek Harness 当前官方 master 为开发预览，可能存在破坏兼容的变更；上游能力不等于本机 0.2.1-rc.2 已逐项验证。

### Harness 数据目录与 profile

[官方路径库说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/util/home-paths/README.md)

- `DSH_HOME` 指定实例数据根，默认 `~/.dsh`。
- `DSH_AGENTS_HOME` 独立指定共享 Agent 指令与 skills 根，默认 `~/.agents`。仅改 `DSH_HOME` 仍可能读取共享内容。
- 显式插件路径配置可能优先于环境变量，需检查实际组合。

[CLI 配置层级](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/cli/reference/README.md)

同一个 `DSH_HOME` 下，不同 profile 仍受 home 级 `cordis.patch.yml` 等共享设置影响。profile 不能直接等同于完整实例隔离。

### skills 的隔离

[skill-filesystem 官方说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/skill/skill-filesystem/README.md)

默认还扫描项目 `.dsh/skills`、`.agents/skills`、自定义目录、实例用户 skills 与共享 Agent skills。该 provider 可用 `includeDefaultRoots: false` 与 `customSkillDirs` 控制目录集合；其他打包或插件提供的 skills 仍需核对。

### CLI 与桌面多开

[官方 CLI help](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cli-help.md)

当前上游有 `web`、`headless`、`sdk`、`acp` 等入口。多个 Web 服务需不同端口，headless 可按任务启动独立进程。

[桌面 CLI 管理](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/desktop/README.md#terminal-command)、[桌面单实例实现](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/desktop/src/single-instance.ts)

官方桌面文档提供 Manage dsh Command… 来注册内置 CLI。桌面有单实例锁，复制或重复打开 App 不能据此承诺多份独立桌面实例。

[headless 鉴权说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/bundle/headless/README.md)

当前上游 headless 的默认鉴权组合与 GUI 不同。现有 GUI 中的登录、凭据或第三方插件不能假定会自动进入新 headless 实例；需要核对具体 profile 与插件组合。

## 本地 WorkBuddy 插件核对

本地目录：`<HOME>/.dsh/profiles/desktop/node_modules/dsh-connect-workbuddy`。

实际阅读 `package.json`、`README.md`、`lib/index.js`、`lib/host-heartbeat-BtMcdOIa.js` 等静态文件；未读取运行时凭据。

- 插件自有 vault、认证副本、pool 状态位于 `DSH_HOME` 下，因此改变数据根可以拆开这些本地文件。
- 默认仍会扫描本机 WorkBuddy/CodeBuddy 桌面认证目录；不同数据根可能发现相同上游账号。
- 插件有指定认证来源与选择参与账号的配置，但本轮未修改、登录、同步或复制认证文件。
- 独立实例不能据此增加同一账号的订阅额度或绕开服务端并发限制；实际可用并发尚未测量。

## 可行性判断

**已核实的配置设计能力**：可以组织多个 Harness 进程，分别给模型/provider、skills、实例数据根、共享 Agent 根与工作目录做配置。

**仍需区分的隔离层次**：

1. 配置与会话隔离：独立 roots、profile、skills 发现范围、插件配置和进程。
2. 工作副本隔离：独立目录/checkout 或按需要使用 Git worktree；避免并行改写同一份文件。worktree 仍共享仓库元数据。
3. 文件访问权限隔离：仅分目录不能阻止同一系统用户的进程读取彼此文件；需要额外 OS 用户、受控容器或虚拟机等边界，并核对挂载与权限。
4. 账号与额度：本地隔离与上游账户配额是不同问题，需按实际账户和套餐核对。

不根据模型名称先定代码、文档或审查能力。后续可用同一真实小任务比较通过率、文档准确性、耗时与额度消耗。

## 补充：模型与 skills 独立，桌面历史集中查看

用户在 2026-11-05 进一步明确：只要求模型和 skills 分别配置，希望各 CLI 的工作记录能在同一个桌面端统一查看。这一要求细化了初次“完全隔离”的含义；后续不应继续假定必须把所有会话记录也分开。

### 需要区分的位置

- 项目工作目录：CLI 读取、修改代码和文档的地方。
- 模型和 skills 配置位置：决定该 CLI 默认使用哪个 provider/model、发现哪些 skills。
- 会话存档位置：决定桌面端能列出哪些工作记录。

更换项目工作目录不会必然导致桌面端看不到历史。桌面端能否列出记录，取决于它读取的会话库、记录格式和会话元信息。

### 已阅读的上游依据

- [CLI profile 层级](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/cli/reference/README.md)：可分别使用 profile 和最终 patch 覆盖；home 级 patch 仍可能影响全部 profile。
- [默认模型服务](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-default-model/README.md)：每个进程有自己的默认 provider/model，保存选择写入当前 profile；已有会话的模型选择另行保留。
- [skills 文件系统 provider](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/skill/skill-filesystem/README.md)：可指定独立目录并关闭默认目录发现；额外 skills providers 需单独检查。
- [基础组合](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/bundle/base/cordis.patch.yml)：会话持久化默认位于 `DSH_HOME/sessions`。

- [设置服务](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/settings/settings/README.md)：配置变更写入活动 profile；覆盖层冲突需要明确处理。

### 可行配置路线（建议，尚未采用或实测）

各 CLI 使用独立 profile/覆盖配置、固定默认模型、独立 skills 目录与会话 ID；共享桌面端读取的会话存档。必要时使用不同工作副本避免同时改写同一份文件。

这样可以只拆开所需的模型和 skills 配置，而保留统一的历史入口。不能把共用会话库解释成所有实例共享同一段对话上下文，也不能让多个进程同时接管同一个会话。查看历史与从桌面继续执行是不同能力，后者还要匹配模型、插件与预设。

当前只确认上游配置设计具有实现依据。本机 0.2.1-rc.2 的有效配置、历史列表刷新与分组、WorkBuddy 路由和记录兼容性仍未运行验证。本轮未改动任何 Harness 配置。

### 进一步核实的两条路线与约束

- 共同 `DSH_HOME`，分别使用 profile/最终覆盖配置来指定默认模型与 skills 集合：可天然共用会话和附件；账号缓存等其他 home 数据也会共享。对本次仅要求模型/skills 独立的目标，这是可优先评估的轻量路线。
- 各自 `DSH_HOME`，仅把 `session-persistence-jsonl` 的 `config.root` 指向桌面读取的会话目录：上游也支持，且无需软链接。现有桌面若确实采用默认目录，目标为 `<HOME>/.dsh/sessions`；落地前须核实实际有效配置，不能直接套用。

[会话存储配置](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/session/session-persistence-jsonl/README.md) 支持 `root`，不同会话可并发写入同一根，但每个会话仅允许一个跨进程写者。版本、日志格式与 compression 需兼容；同一根混用 zstd 与 none 不受支持。

独立 home 只共享 sessions 时，附件字节与标题等投影缓存仍需额外处理，不能承诺所有内容自动完整显示。全文检索的 SQLite 派生索引为 single-owner，不应让多进程共用同一个数据库。
