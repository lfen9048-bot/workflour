# Kiro 接入可行性

用户询问 Kiro CLI 或桌面端能否接入现有工作流。本次按 search-first 阅读当前记录、实际脚本与实例配置，再核对 Kiro 官方文档和 OpenMausBot 固定版本源码。仅只读调研与文档记录，没有安装、登录、调用模型、更改运行配置、升级或重启服务。

## 当前环境与问题定位

- 已有记录说明 Coder、Doc、Antigravity 三实例和手机公网入口已跑通；本次没有重复验证这些能力。
- 实际 OpenMausBot 包与 run-omb.sh 均固定 0.1.143，配置存在 omb-coder、omb-doc、agy-gemini，均走 customAcp。
- 本机 Kiro.app 已安装，版本 1.4.121；PATH 中没有 kiro-cli 或 kiro。只说明未发现可直接调用的独立 CLI，不能据此断言其它私有运行时绝不存在。
- 现有 run-acp-agent.sh 已有 DSH 专用的 resume bridge；它只解决 DSH 的 load/resume 差异，不应直接套在 Kiro 上。

## 技术可行性与接法

**优先通过官方 Kiro CLI ACP 接入，作为第四个 Agent 候选。**[官方 ACP 文档](https://kiro.dev/docs/cli/acp/)明确提供 kiro-cli acp，使用 stdio JSON-RPC，支持会话、流式输出、取消等标准能力。它是隐藏子命令，--help 未列出不代表没有 ACP。

CLI 3.0 起默认 V3；--agent、--model、--effort 等是 V2-only，不能与显式 V3 混用。是否支持具体扩展以 initialize 实际能力为准。[命令参考](https://kiro.dev/docs/reference/cli-commands/)、[harness 说明](https://kiro.dev/docs/cli/agent-harness/)

[OpenMausBot v0.1.149 Release](https://github.com/milind-soni/OpenMausBot/releases/tag/v0.1.149)（2026-11-08）已宣布内置 Kiro。对应[实际驱动](https://github.com/milind-soni/OpenMausBot/blob/v0.1.149/server/drivers/acp/kiro.ts)使用 kiroAgent，执行 kiro-cli acp --agent-engine=v3 --auth-method=cli；源码注明检查过 CLI3.1.0，包含 CLI 登录检测、模型发现、Kiro hooks 处理和 autopilot/审批模式设置。这里是源码证据，不是本机验证。

本次可见最新 Release 为 [v0.1.150](https://github.com/milind-soni/OpenMausBot/releases/tag/v0.1.150)（2026-11-09）；本机仍为0.1.143，其固定 tag 的 kiro.ts 不存在，本机编译产物也未找到 Kiro 驱动。

可评估两条路线：

| 路线 | 优点与缺口 |
| --- | --- |
| 新版内置 Kiro 驱动 | 已专门处理 V3 模型、hooks、权限模式；更适合优先做隔离验证。但涉及 OpenMausBot 升级，需检查现有三个实例、配对、公网入口及本地改动兼容 |
| 保持0.1.143，新增 customAcp | 通用ACP机制有接线基础，但旧客户端对当前Kiro的认证、扩展请求、权限和模型选择未实测，不能只填一条命令就承诺完整可用 |

助手建议先用独立测试数据目录与端口评估新版原生驱动，不直接覆盖当前运行服务。通过后再决定合并升级。此建议尚未获实施授权。

## 桌面端、skills 与历史的区别

- Kiro IDE 可以继续打开同一项目，供人编辑、审阅、维护规格文件。没有找到把“正在运行的 IDE 窗口”直接当成 OpenMausBot Agent 服务的官方公开入口；外部接入应优先指定 kiro-cli，而不是只启动桌面窗口。[官方 ACP 集成](https://kiro.dev/docs/acp/)
- Kiro 提供自定义 agents、steering、skills 等配置；官方描述当前统一 harness 会在不同原生客户端使用这些配置，但实际版本与资源加载范围需验证。独立角色资源不等于全局 skills 或文件访问天然隔离。[自定义 agents](https://kiro.dev/docs/custom-agents/)、[skills](https://kiro.dev/docs/skills/)、[架构说明](https://kiro.dev/docs/how-kiro-works/)
- 新 Bot 的对话可由 OpenMausBot 记录，因而存在继续复用当前手机入口的路线；不意味着既有 Kiro IDE 聊天会自动导入或与 OpenMausBot 双向同步。

## 登录、额度和官方使用范围

ACP 走 Kiro 自己的登录和账户，不是 WorkBuddy 模型来源。CLI 需要自己的有效登录；相同账号可关联订阅，但桌面已登录不等于 CLI 已登录。[ACP 认证说明](https://kiro.dev/docs/cli/acp/)

必须区分技术可连接与官方使用范围：[Kiro FAQ](https://kiro.dev/faq/)“With which tools can I use my Kiro subscription?”明确允许 Kiro 原生客户端、ACP 兼容 IDE 和软件开发自动化，同时限制第三方 automation harness 将请求路由到 Kiro 原生接口之外的用法。不能仅因 OpenMausBot 有驱动，就断言此第三方用法已经获得 Kiro 官方认可；具体是否符合该范围本次没有结论。不要将其改造成提取登录 token 的模型转发 API。

## 当前结论与停止位置

技术上可作为第四个 Agent 候选，推荐研究官方 CLI＋新版内置驱动。桌面端适合配合编辑，未发现可直接当作该系统执行入口的公开方式。接入前尚需明确官方订阅适用边界，并验证实际 CLI 登录、协议、模型、skills、工具、审批和续聊；所有这些都没有在本机运行。

用户本次是可行性询问，未授权安装、升级或修改现有工作流，也未确认新增角色。未启动实施计划。
