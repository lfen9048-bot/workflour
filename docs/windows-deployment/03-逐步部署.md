# 从源码到 Windows 完整流程

所有命令由 Windows Agent 执行。每步记录真实版本、执行结果、证据和未完成项；先跑通单实例，再扩大。下列 Windows 启动器是**待实现目标**，不是仓库已提供的可运行功能。

## A. 盘点、读记录、登记路径

先完成第00章的必读顺序，阅读当前七角色与 Plan/Code 流程及工作记录。建议：

```text
C:\workflour\                              源码及适配
C:\workflour-projects\                     每个产品独立目录
C:\workflour-notes\多Agent协作开发工作流\   Obsidian
%USERPROFILE%\.dsh\                       实际位置需确认
%USERPROFILE%\.openmausbot\               实际位置需确认
```

应用状态放本地磁盘，避免 OneDrive 对运行文件的占用干扰。存在已有安装时先读配置，不另建第二套服务。复制 `deployment.example.json` 为不入Git的本机登记文件，填写程序绝对路径、版本、目录和稍后生成的新Bot ID；不填token。仓库工作记录可作为新知识库的历史参考，另建Windows首页和本次交接，不能改历史Mac验证为Windows通过。

```powershell
$env:PYTHONUTF8 = '1'
Set-Location 'C:\workflour'
New-Item -ItemType Directory -Force 'C:\workflour-projects' | Out-Null
New-Item -ItemType Directory -Force 'C:\workflour-notes\多Agent协作开发工作流' | Out-Null
```

仅在路径盘点无冲突后执行。GitHub克隆不依赖旧ZIP的MANIFEST；记录仓库提交与本机修改。

## B. 软件、登录与单模型

按第02章安装，先做到：Node/Python/Git/PowerShell可定位；DSH Desktop正常；WorkBuddy已在同一Windows用户登录；插件5.13.1加载；AGY原生登录；OMB0.1.143单一前台服务可打开。

在DSH desktop profile确认实际provider、模型与思考档位，并最小请求验证DeepSeek、GLM、Kimi。每次只报告必要的模型来源、结果和时间，不输出密钥或思考正文。缺额度明确阻塞，不用替代模型伪造目标模型成功。AGY也独立完成真实工具调用，不能用DSH测试代替。

## C. 实现一个 Windows ACP 入口

第04章适配后，先建立 `omb-wf-assistant`。建议新增 `run-acp-agent.cmd`／Python启动器与 `run-agy-agent.cmd`；命名只是目标，执行前确认文件真实存在。

DSH入口必须：支持OMB的`--version`探测、固定DSH_HOME和profile、使用`acp-resume-bridge.py`保留`session/load → session/resume`、追加正确的pool overlay/title/fallback patch、stdin/stdout保持原始协议字节。诊断仅stderr；停止只清理自己子进程，不杀所有Node。

参考Mac `setup.sh` 生成以下ACP结构，**不要直接运行Mac脚本**：

```text
%USERPROFILE%\.dsh\profiles\omb-wf-assistant\
  package.json
  cordis.yml
  cordis.patch.yml
  pnpm-workspace.yaml
  node_modules\  本机安装，不复制Mac二进制
```

`package.json` 的bundles形状：

```json
{
  "name": "dsh-profile-omb-wf-assistant",
  "private": true,
  "dependencies": {"dsh-connect-workbuddy": "5.13.1"},
  "dsh": {"profile": {"bundles": [
    "@deepseek-ai/dsh-base", "@deepseek-ai/dsh-acp-app", "dsh-connect-workbuddy"
  ]}}
}
```

`cordis.yml` 初始为 `[]`，`pnpm-workspace.yaml` 初始 `packages: []`；角色patch由相应模板生成，填Windows技能路径、原生账号引用和实际模型。宿主内置bundles由DSH处理，不猜公共npm包名安装。原生依赖命令示例：

```powershell
dsh plugin --profile omb-wf-assistant add dsh-connect-workbuddy@5.13.1
```

操作后核对profile仍是ACP，不被变成desktop/web。生成器须幂等、先备份、保留凭据、不得依赖旧Mac `omb-doc`。先验initialize/session-new、目录/配置读取，再真实读写演练文件；握手成功不代表模型成功。

## D. 扩展六个 DSH profile 与一个 AGY

DSH角色键：`wf-manager`、`wf-plan-lead`、`wf-plan-review`、`wf-code-review`、`wf-code-helper`、`wf-assistant`。实例为`omb-<角色键>`。`wf-code-main`只是职责键，运行时为独立`agy-gemini`，不能为它另建DSH profile。

原生customAcp配置形状如下，仅用于说明结构；Windows实际命令解析须读安装版本实现后验证：

```json
{
  "instances": {
    "omb-wf-assistant": {
      "driver": "customAcp",
      "displayName": "DSH 通用助手",
      "config": {"cli": "C:/workflour/run-acp-agent.cmd wf-assistant"}
    },
    "agy-gemini": {
      "driver": "customAcp",
      "displayName": "Antigravity 主编码",
      "config": {"cli": "C:/workflour/run-agy-agent.cmd"}
    }
  }
}
```

按键合并配置保留其他实例。带空格路径不盲拼shell字符串；核对`.cmd`或`python.exe + launcher.py`形式。六个profile各自读取职责和按需技能，AGY用原生`agy acp`；Mac的`--stdio`仅在目标版本help支持时沿用，不注入DSH备用钩子。

## E. 创建七 Bot、职责和路由

通过本版本原生API/UI创建七角色；仅注册实例不会自动生成Bot。以`roles.json`和第01章为目标，读回名称、实例、默认模型、档位、Full及DSH真实权限。保存新Bot ID，向Soul追加精确peer路由和Windows项目路径。不要沿用Mac部署文件的UUID。

大管家作为chief/默认入口，大管家与通用助手置顶；Plan Team与Code Team分别归组。新机没有历史不必造旧Bot或测试入口。系统Maus若受保护，只隐藏入口，不改数据库硬删。

若使用`provision-team.py`，先适配路径、API与生成逻辑；不能对新机执行旧retirement删除清单。专业技能的符号链接需要Windows合法链接或实际文件复制，同时保留来源与许可证，确认冷启动后能读。

## F. 模板、账本与原生委派

先移植文件锁、链接检查和Windows子进程，再创建空演练项目：

```powershell
py -3 scripts/new-project.py 'C:\workflour-projects\windows-plan-code-demo' --name 'Windows Plan Code 演练' --workflow plan-code --git
```

`--workflow plan-code` 必须明确；默认manual和历史code-team不是当前目标。同时检查`templates/project/`与`templates/plan-code/`及隐藏`.workflour`材料完整。项目内checker是复制品，改公共版后新建或受控同步，不能只改根脚本而遗留旧检查器。

Plan负责人初始化账本，作为`--actor plan-lead`唯一共享状态维护者。研究／定稿用record，其他阶段claim→原生派单→receipt→result→advance。实际角色键是`plan-lead/plan-review/code-main/code-review/code-helper`，不是带`wf-`的profile键。

Code用项目checker执行真实测试，首次文件清单用重复`--files`声明，返回detached JSON；Plan补齐实际code_files/baseline/work_items后导入。代码变更使旧快照失效。运行中补充若产生新requestId，必须登记supplement并等主单和全部补充完成后复审。详细命令以[流程接口](../../integrations/openmausbot/PLAN-CODE-WORKFLOW.md)与脚本help为准。

## G. 模型控制、账号池、成本顺序与签到

逐Bot刷新实际模型目录，验证任务选择与Bot默认互不混淆。`bot-model.py`的runtime识别需适配Windows启动器。同运行时空闲任务可改，跨运行时新任务＋交接＋保留旧记录；原生Ask要求不能绕过。

桌面插件内勾选获授权的国内两个账号，国际池保持关闭，仅选当前账号。配置同步使用独立临时完整patch层，保留目标profile的模型目录、图片配置、其他字段；不能用仅含pool的后置patch抹掉整个WorkBuddy配置。Windows需改写Ruby路径和文件权限/进程归属判断，见第04章。

成本顺序：已实时核实免费（国际优先）→区内按插件规则排队后比较国际/国内队首临期时间→其他WB积分→已配置API。默认DS只自动选等价DS通道；Kimi/GLM正常保留。明确额度错误后才尝试DS/GLM备用并最终API。旧0折缓存、目录失败、普通429、网络问题都不是跳付费的理由，不能承诺扣指定积分包。

适配并测试`workbuddy/client.mjs`的Ruby读取、`checkin.mjs`的Python fcntl锁后，才能执行：

```powershell
node integrations/openmausbot/workbuddy/checkin.mjs --daily-checkin
node integrations/openmausbot/workbuddy/checkin.mjs --status
node integrations/openmausbot/model-fallback/status.mjs --daily-check
```

签到仅国内个人账号，查→未签才领→读回确认；超时未确认不重复领。`--status`只读本地日志。建立Windows自己的每日**北京时间13:00**任务，先签到后检查恢复；不复制Mac automation ID。恢复逻辑本身以13点后的新回合为界，不打断运行中回合，不覆盖手动设置。AGY不自动跨运行时。

## H. 浏览器能力与真实体验

依第02章创建Windows独立Playwright环境，修改`CAPABILITIES.md/BROWSER.md`中的本机路径；不复制Mac `.tools/browser`。用隔离context，不读取用户Chrome profile。各角色核验网页检索、文件、命令与截图读取；只有截图实际传入并读到，才算图像能力。

网页preview只反馈方向，最终experience必须另开会话实际操作桌面/手机尺寸、逐条验收、保存截图与交互日志。能力缺失写blocked；不让代码测试替代体验通过。

## I. Obsidian、分类与精简工作台

观察器适配后用真实路径注册项目：

```powershell
py -3 scripts/workflow-observer.py register --project 'C:\workflour-projects\windows-plan-code-demo' --vault 'C:\workflour-notes\多Agent协作开发工作流'
py -3 scripts/workflow-observer.py sync

```

观察器只观察登记项目、显示异常，不派单或改共享状态。DSH分类按真实cwd、工作区与“角色 · 编号 · 任务”标题；ACP排队，桌面Host唯一写入，桌面关闭时如实待处理。不要改历史执行目录或整理无关会话。

工作台精简层在`integrations/openmausbot/workbench/`，保留模型、思考、新任务、停止、权限、记录及高级设置。私有runtime依赖符号链接，Windows必须适配合法链接或完整复制并改manifest校验；先核对固定源版本/哈希，再做真实桌面和手机视觉检查。不改全局安装包、不删除后端能力。
