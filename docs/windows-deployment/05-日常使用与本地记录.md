# 部署完成后怎样用

以下以Windows各项验收完成为前提。日常只需要工作台，不要求用户先执行终端命令。

## 发一个新项目

打开工作台，选**大管家 → 新对话**，发送：

> 帮我新建“每日三件事”，放在 C:\workflour-projects\daily-three。做一个中文网页，最多保存三件事，可以完成、删除、只看未完成；刷新后仍保留。电脑和手机都要好用。由你转给Plan团队制定方案，再让Code团队实现、审核和实际体验。你们负责初始化目录与执行命令，最后给我入口和验收说明，停在待我验收。

已有项目就写“继续这个已有项目”，不要再要求新建。路径不明确时团队澄清，不猜目录覆盖旧文件。大管家转交Plan负责人，复杂规划由Plan两人完成；普通小任务由Gemini主编码，协作编码不必每次参加。

## 看进度和记录

对大管家说：

> 只查看每日三件事的当前阶段、负责人、等待原因和下一步，不重派任务。

大管家应依据Plan账本和汇总回答，不自己读代码、算哈希或再做审核。要看细节，打开Plan负责人及对应成员任务。状态区分研究、方案评审、实现、技术审核、实际体验、审批、等待模型、失败、停止、待用户验收。

工作台是对话入口；项目`HANDOFF.md`和账本是持久状态；Obsidian是便于阅读的观察镜像。留意同步时间，旧记录不能当当前绿灯。

## 改模型或思考程度

对大管家或通用助手说：

> 打开模型设置卡，把“Code · 独立审核”的当前空闲任务换成WorkBuddy的DeepSeek V4.1 Flash，只改这次任务；思考程度选菜单里真实可用的High。

需要以后都用则明确“设为Bot默认”。卡片核对Bot、任务、区域/额度来源、运行时、模型、真实档位和作用范围。顶部原生菜单可能修改默认，不能保证只改当前任务。

大管家正在处理自己的设置请求时无法改自己，交通用助手办理；反之亦然。忙碌回合先完成或用户明确停止，不为改设置暗中中断。跨DSH/AGY会新建任务、读交接、保留旧聊天和原生Ask要求；不承诺无损迁移或自动继承Full。

## 停止、继续与运行中补充

在实际运行任务中点停止，已写文件不会撤销。继续时说：

> 继续刚才停止的审核。先核对原回执、当前代码和副作用，只恢复未完成部分，不重做已经完成的工作。

等待审批、排队、运行中，或成员已在另一窗口直接续跑，都不能再派一份。停止后的继续来源要明确，不能套用更早的“继续”。

运行中可以向原负责人补充要求。当前ACP不保证即时插入，可能成为同一worker的新queued回执；团队要登记并等全部补充完成后才复审。若补充失败，说明具体哪项受阻，不重跑整份主任务。用户询问进度不等于允许继续。

## 额度和每天13点

默认DeepSeek按实时价格选择等价通道：**已核实免费 → 国际/国内临期积分 → 其他WorkBuddy积分 → 明确额度问题后的既有DeepSeek API**。国内仅勾选的账号，国际池关闭仅当前账号；区内遵循插件池顺序，跨区比较队首最早到期，不固定A/B轮流，不指定扣某个包。

Kimi/GLM默认正常保留，明确额度问题后进入DS/GLM备用。手动选择优先；网络、超时、普通429、排队、读取价格失败不等于额度用完，不因此直接花API。旧“0折”缓存不能证明当前免费。实际通道看【系统·模型状态】和请求记录。

北京时间**13:00后新回合**重新检查原模型与规则，运行中不打断，Bot默认不改。Windows自己的定时任务同一时间检查国内个人账号签到：先查、未签才领、读回确认；已签显示already_verified，未确认不会误报或重复领。Mac离线/Windows睡眠时都不能保证准点执行。

可以让大管家“查看今天本地签到与额度恢复检查结果”；它应说明记录时间。本地状态不是刚刚实时查询。AGY失败不自动换DSH，团队保存交接并如实说明。

## 最后验收

Plan交付入口、目标对照、测试和技术审核、真实体验、限制与证据，大管家做简短汇报。用户实际使用后明确“我验收通过”；有问题给操作步骤、预期和实际现象。Bot的PASS、账本一致或测试全绿不代替用户验收。

## 本地保存什么

| 位置 | 内容及维护者 |
| --- | --- |
| 需求/PLAN/任务材料 | 用户原话、依据、假设、验收；Plan维护共享内容 |
| `HANDOFF.md`、`.workflour/handoff.json` | 阶段、交接、当前代码与证据快照；Plan/受控检查器 |
| `.workflour/coordination.json` | claim、主回执、supplement、恢复和返工历史；Plan唯一维护 |
| `records/<role>/` | 各角色独立研究、实现、审核、体验记录 |
| `.workflour/evidence/` | detached测试记录、命令、退出码、输出；Plan导入 |
| 实际DSH/OMB数据目录 | profile、原生会话、Bot设置、委派记录及私密账号状态 |
| Obsidian `07-自动记录/` | 已登记项目进度、可见记录、异常和证据链接；观察器生成 |
| 本机签到/备用目录 | 日签到状态、模型选择及检查摘要；不存密钥或推理正文 |

新会话隔离工作记录，但长期记忆、职责和项目共享文件仍可能提供背景，不等于严格清空所有上下文。Obsidian和Git工作记录不是原生会话数据库的精确恢复备份。

代码和知识库可备份到合适位置；账号与数据库单独私密备份，使用产品支持的一致性方式，不能活跃写入时只复制一个SQLite文件。不要提交`.dsh`、`.openmausbot`、API key或实际账号目录。新Windows部署不自动接管Mac正在跑的任务。
