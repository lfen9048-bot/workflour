# Workflour Windows 部署交接

更新：2026-11-11。本目录随 GitHub 源码提供，供 Windows 上的 Agent 学习已实施的方法、完成平台适配和验证。

**当前可复现的是 Mac 上的实现与经验，Windows 仍待实际移植和验收。** 克隆仓库、软件装好或模型菜单出现，都不能写成“Windows 工作流已搭好”。本文不要求使用者替 Agent 执行终端命令。

## 先恢复上下文，再安装

Windows Agent 必须按顺序阅读：

1. 根 [README](../../README.md) 与 [AGENTS](../../AGENTS.md)。Mac 知识库不可访问时，改读仓库里的记录副本，不要伪称已经读取原知识库。
2. [项目大纲](../PROJECT-OUTLINE.zh-CN.md)、[当前状态](../CURRENT-STATUS.zh-CN.md)。确认用户目标、已实施功能、实际验证与未完成事项。
3. [工作记录首页](../project-records/首页.md)、[需求与待定事项](../project-records/01-需求/目标与待定事项.md)、[记录约定](../project-records/记录约定.md)，再按首页链接读与本次部署有关的有效决策、搭建和验证记录。
4. [当前 Plan / Code 流程](../../integrations/openmausbot/PLAN-CODE-WORKFLOW.md)、[七角色配置](../../integrations/openmausbot/team-v2/README.md)、`agents/wf-*/SOUL.md` 与 `SKILLS.md`。记录用于解释来源；当前源码和最新决定用于确认事实。
5. 本目录 01–06、08、09；07 是资料查找索引，不是执行顺序。

先用简短中文说明当前目标、已经验证的部分、Windows 差距和下一步，再开始实施。不能沿用历史双 Bot、8 Bot、三方长讨论或 08:00 计划覆盖最新安排。

## 要搭出来的使用方式

使用者在 `http://127.0.0.1:8799` 向**大管家**交需求。大管家转给 **Plan · 项目负责人**，后者调研与初案 → Plan 评审 → 定稿 → Gemini 主编码 → GLM 技术审核 → Plan 真实体验 → 用户验收。

共 **7 个 Bot：5 个主流程角色＋协作编码、通用助手两个按需角色**；底层为 **6 个 DSH profile＋1 个 Antigravity 运行时**。普通小任务只有一位主编码，不为了证明“多 Agent”强行拆成两人写。

## 获取代码与交给 Agent

仓库入口：[lfen9048-bot/workflour](https://github.com/lfen9048-bot/workflour)。它是私有仓库，目标电脑先使用已获访问授权的GitHub账号登录；不在命令里拼token。由Agent克隆，或在GitHub下载仓库ZIP后解压：

```powershell
git clone https://github.com/lfen9048-bot/workflour.git C:\workflour
```

建议项目目录 `C:\workflour-projects`，知识库 `C:\workflour-notes\多Agent协作开发工作流`；源码目标已存在时先盘点，不直接覆盖或重新clone进非空产品目录。

把 [08-Windows-Agent接手提示词.md](08-Windows-Agent接手提示词.md) 整段发给目标 Agent。登录与必要系统交互由用户本人完成，其余安装、路径登记、适配、配置和测试由 Agent 负责。新 Windows 机重新登录，不搬 Mac token、API key、SSH 私钥或运行数据库。

## 仓库携带的内容与边界

重点是 `agents/wf-*`、共用技能及许可证、`scripts/`、`integrations/openmausbot/`、`templates/project/` 和 `templates/plan-code/`（含隐藏模板文件）、测试源码，以及 `docs/project-records/` 中的可携带工作记录。[Mac脱敏验证与截图](../evidence/2026-11-11/README.md)用于理解证据，不替代Windows测试。脚本中仍可能有 Mac 路径和原实例映射，必须适配。旧headless的`setup-agents.sh`、`run-agent.sh`不是新机安装入口；本次不要直接运行。

不把应用账号目录、凭据、node_modules、真实公网配置、原始聊天数据库和自动聊天镜像当作部署材料。原生会话与派单链不能靠 Markdown 精确恢复。仓库没有包含的本地证据应标为“来源记录存在、原件未随仓库”，不能凭断开的链接宣称验证成功。若另行生成 ZIP，只在确有清单时使用其 MANIFEST 校验；GitHub 克隆不假定存在旧 ZIP 根目录文件。
