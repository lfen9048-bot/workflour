# 2026-11-12 子代理代码审核

用户要求先由子代理审查，再使用正式团队和模型完成一个简单前端。两个子代理分别检查技能验证器和项目流程，另一位只读核对角色模型、账号池与原生入口。本文记录代码修复；业务实跑结果另行记录，离线测试不等于完整交付通过。

## 发现并修复

| 问题 | 修复后的行为 |
| --- | --- |
| 读取证据按字符串匹配路径，会把相似文件名或备注中的路径算成实际读取 | 只采用工具结构化文件路径，规范化后精确匹配 |
| 图片读取已被识别，但权限分支漏掉 `read_image` | 仅明确指向隔离样例目录内图片的读取放行；范围外或没有目标仍拒绝 |
| 收尾计算哈希时文件消失，会丢失整份验证结果 | 保留原始运行结果；逐文件记录无法读取的原因，完整性标记为未核实 |
| 要求或先前审核报告改变后，旧验收结果仍可机械通过 | 新账本定稿时锁定原话、验收要求与 spec；后续检查核对该锁和当前有效轮次的报告哈希 |

前三项只影响隔离技能验证器。最后一项用于新建的 plan-code 项目：`workflow_version=3`、`freshness_version=1`。历史返工轮次保留，不把旧代码快照强行与新代码比较；旧账本显示 `legacy`，不补造历史证据，也不自动修改旧项目内的检查器。

## 正式实跑的入口差异

新任务显式请求 Full 被 OpenMausBot 原生策略拒绝，提示需要专门的共享工作区策略。该请求没有创建任务或派单。随后使用产品支持的 Ask 新任务入口，只向大管家提交一次“阅读清单”任务；不改 Bot 默认权限、服务器安全策略或模型配置。后续审批及业务结果须按实际记录，不能据此称为全自动 Full 验证。

## 后续复核与流程补强

上面的108项是首轮记录。后续按实际磁盘、原生回执与当前代码重新核对，发现“工具回合完成”仍可能带回语法错误或缺失测试，且原生补充回执、交接文字和读图线路需要单独处理。以下代码已补入本轮工作区；本节不代表正式网页流程或Ubuntu目标机已验收。

| 问题 | 当前实现 |
| --- | --- |
| 实现任务有原生completed回执便可能提前进入技术审核 | `result implement completed`及`advance review`两个入口都要求当前代码快照、已导入的真实成功测试、未被改写的测试输出和完成的工作项；不提前要求独立审核结论 |
| 返工/补充混用回执容易重复派单 | 先准备精确派单意图，再由工具钩子核对发送者、接收者、内容与阶段；发送前记sending，结果不明保持uncertain，按原生回执核对，不自动重发 |
| 任务需要读图，但省额度线路只支持文字 | ACP成功new/resume时独立保存真实Bot/thread绑定；从原生assignment关联的意图取image要求，先筛选同系列已实测读图线路，再沿用费用顺序；无法确认时明确受阻，不跨模型或转付费API，不覆盖手选 |
| 交接文本仍写“等待补充回传”，回执其实已完成 | 观察器分别显示按账本/原生回执核对的下一步与可能滞后的负责人原文，并提示更新；不自行推进或改共享状态 |
| 原生适配器把read_image归类为read时绕过图片专门限制 | 精确工具名read_image优先识别；read/other两种kind都限制在隔离图片目录，图片不冒充Markdown技能文件已读取 |

模型图片菜单或勾选只是能力声明。启用图片路由还须本机探针记录、精确provider/model、WorkBuddy版本及证据文件哈希一致，并检查当前图片勾选与账号目录。缺失、变化或无法读取都不是通过。会话身份文件与手动模型revision分开，不记录MCP凭据。

## 本机实际启用核验

维护者使用Electron自带Node读取真实DSH ToolRuntime，执行前拒绝、合法单次发送、原生拒绝保留三项全部通过，0跳过；这与上面普通Node环境的skip分别记录。Plan profile通过initialize/new/close无prompt握手，正常退出。旧开发团队ACP进程已自然回收，新机制在后续会话加载，未重启或打断其他团队。

通过WorkBuddy原生设置保存，只向国际图片列表追加`deepseek-v4.1-flash-sg`，保留其他勾选和四账号池。一次隔离真实请求成功调用`read_image`读取随机八位数字，实际来源为WorkBuddy国际版SG。探针原评分把系统路线通知混入答案而误报失败，原记录保留，另用严格答案哈希、唯一已完成图片工具与真实来源核验后裁定通过。运行时重新核验原报告及裁定的关联哈希，不能只相信登记的passed。该能力仅在本机当前插件版本下确认，不复制到Ubuntu充当目标机证据。

阅读清单业务接续已从原大管家入口转到原Plan会话。Kimi一个国内账号限流、另一个额度不足，用户明确选择仅当前任务临时使用DeepSeek High；七角色默认配置不变。当前代码仍须处理持久化`_uid`重复或类型异常导致单书操作错误的问题，之后重新独立技术审核与真实体验；维护代码通过不代表业务网页已经验收。
