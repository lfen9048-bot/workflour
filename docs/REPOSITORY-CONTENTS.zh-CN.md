# 仓库内容与接手边界

这份私有仓库用于在 Windows 延续同一套 Workflour 方法。它是经过筛选的源码和记录快照，不是原 Mac 整机备份。

## 已包含

- 当前七角色的职责、按需技能、共享能力说明、上游来源与许可证。
- ACP 接入、会话恢复、模型控制、额度优先、签到、工作台精简、阶段账本、项目模板和 Obsidian 观察器源码。
- 全部主线单元测试及协议探针；模板内 `.workflour`、`.specify` 等必要隐藏文件完整保留。
- [当前状态](CURRENT-STATUS.zh-CN.md)、[项目大纲](PROJECT-OUTLINE.zh-CN.md)、[Windows 详细交接](windows-deployment/00-从这里开始.md)。
- [70 篇手写工作记录](project-records/README.md)，包括需求、方案变更、失败原因、搭建日志与验证结论。
- [筛选验证摘要和真实截图](evidence/2026-11-11/README.md)：模型线路、签到、重启不重派、迁移、工作台和网页体验。
- “今日三件事”网页源码/测试，以及 ACP 探针使用的小型 textstats 样例。

## 有意不包含

- `~/.dsh`、`~/.openmausbot` 等真实账号/凭据目录、API key、登录状态、SSH 私钥、数据库和配对信息。
- 全部原始聊天、`07-自动记录`逐会话原文、完整私有备份与未筛选附件。
- 真正运行中的项目账本、Bot UUID 部署映射、实例默认状态、VPS Caddy 实际配置。
- 旧 `agent-coder` / `agent-doc` 两份完整 headless 配置（包含本机账号池选择）；新主线薄角色配置保留。旧入口脚本留作历史源码，不能在干净检出上假设旧配置已存在。
- Python/浏览器环境、node_modules、下载的软件和旧 Windows ZIP。依赖必须在目标机按官方来源重新安装。

这些数据仍在原 Mac；本轮 Git 上传没有删除、移动它们，也没有为了上传停止或重派工作台任务。`.gitignore` 约束后续暂存范围；不要用 `git add -f` 把真实运行状态加进来。

## Windows 接手要做的事

1. 使用自己的 GitHub 登录克隆私有仓库。
2. 从 [08 接手提示词](windows-deployment/08-Windows-Agent接手提示词.md) 开始；先读当前状态，再看历史。
3. 安装 DSH、WorkBuddy 插件、Antigravity、OpenMausBot 和测试依赖，重新登录。不要从 Mac 复制会话凭据。
4. 逐项适配路径、脚本、文件锁、进程树、符号链接与后台服务；不要执行原 Mac 的 VPS 或清理操作。
5. 新建本机角色与项目，生成新的 ID 和知识库位置；在 Windows 完整跑一次实际项目后才写部署通过。

仓库保留 27 个项目内相对技能符号链接，所有目标都随源码上传。Git for Windows 若将它们检出为文本文件，接手 Agent 应核对共享技能目录后使用真实目录副本或受支持的链接方式，不能把“路径存在”当成技能已经能读取。

原业务测试没有随导出被改写。本次只对一项工具包测试作适配：旧私有 headless profile 不在干净检出时跳过对该文件的哈希读取；若原文件在本机，仍验证初始化没有改动它。

## 记录可信度

历史笔记中“计划”“已执行”“已验证”严格区分。当前默认是七角色、`plan-code`、北京时间 13:00；旧两层八 Bot、三方规划或 08:00 不能覆盖新决定。技术验收通过不等于用户已验收，也不等于 Windows 已通过。

绝对路径、旧模型和服务版本在源码中仍可能出现。移植要看实际代码，不是把文本替换完成就算运行成功。导出记录的内部链接已转为仓库相对路径；没有携带的私有证据会明确标注“未上传”。
